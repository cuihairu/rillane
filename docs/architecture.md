# Current implementation and boundaries

This is an implementation reference, not another architecture design. The **single current design baseline is [v1 architecture](design/architecture-v1.md)**, supported by [concepts](design/architecture-concepts.md) and [Debug/MCP](design/debug-and-mcp.md). Those targets are not implemented as a whole.

## Code organization

| Directory/module | Current responsibility |
|---|---|
| `apps/rillaned` | Configuration, runtime assembly and HTTP control plane |
| `apps/rillanectl` | Configuration utilities, control queries, subscriptions and certificates |
| `apps/rillane-mcp` | Optional stdio MCP adapter (`RIL-067`): off by default, no listener port — an explicit-start client of the control plane over the shared `rillane-app` boundary; stdout carries protocol messages only (one JSON-RPC message per line, official 2026-07-28 modern-era contract with per-request version gates, `server/discover` and cancellation suppression), logs go to stderr, bounded per-request execution (30 s cap), EOF exits cleanly leaving no background work (probe jobs live daemon-side under server quotas); session authorization scopes come only from startup flags (default read-only, `RIL-068`) with a fixed-window per-minute tool-call rate limit |
| `rillane-core` | Flow/FlowContext, RouteDecision/RoutePath, forwarding and UDP contracts; flow/plan/session contracts (`plan` module: one-way RoutePlan mapping, SessionPin, TCP/UDP association boundary); two-phase ingress contracts (`inbound` module: `InboundSpec`/`InboundFactory`, `PendingStream`/`PendingAssociation` with one-shot responders, capture origin for TUN); outbound establishment contracts (`outbound` module: `StreamOutbound`/`DatagramOutbound`, `OpenContext`, opened stream/association, staged `OpenError`); session executor wiring (`session` module: one authoritative accept→establish→reply→pump path, no replay after business exchange); capability assembly and pool resource types (`resources` module: `assemble_backend` is the single support-table authority — declared capabilities, transport stack, reuse class and feature gates are merged and cross-checked once at assembly, and importer/runtime/connector consume the same validated `AssembledBackend` instead of each maintaining a support table; pool resources are typed as prewarm-consume / exclusive-target-bound / multiplexed with `LeaseKey` carrying generation/node/target/credential/security tags so different tenants, credentials or generations structurally cannot share a lease, and `LeaseGuard` is the single owner handle for consume/drain/cancel/close transitions; TLS resumption and connection reuse are distinct resources — resumption requires `tls` in the stack and excludes multiplex); underlay dial and transport composition contracts (`underlay` module: `UnderlayDialer` is the only socket-opening entry — DNS, interface binding and platform bypass are applied when the raw socket opens, transports receive already-connected streams so DNS/bypass logic structurally cannot be duplicated; `TransportStack` validates TLS/WS/gRPC/HTTPUpgrade orderings against an explicit grammar at assembly time — illegal orderings are rejected statically; QUIC/WireGuard are `TransportClass::NativeChannel` holding their native resources, never forced into plain stream wrappers; `PlatformBypass::apply_raw` injects bypass into externally-opened sockets by raw handle, and components declaring `CannotInject` are rejected at assembly under a required bypass policy — no injection means no loop-freedom guarantee); authoritative business traffic accounting (`meter` module: `SessionMeter` is the single authoritative counter at the business-channel boundary — direction is semantic client→target / target→client, never flipped by socket read/write side; partial writes add only actually-transferred bytes and fallback retries never double-count business totals, zero-length UDP still counts one datagram; underlay handshake/encryption overhead and shared multiplex common overhead stay in separate fields never merged into business — overhead that cannot be precisely attributed is explicitly marked instead of fabricating per-flow precision; when attempt A fails and B carries the traffic the session total counts once with the carrier attributed exactly once; `TrafficOrigin` is fixed at construction so probe/prewarm aggregate in their own buckets and never absorb into user traffic; ingress/egress views are projections of the same business volume — adding them is not total usage); session observer (`observer` module: a low-frequency stage-event surface for ingress/establish/handshake/fallback/close — high-frequency bytes go to the `SessionMeter` counter and no per-read/write event is ever allocated; every event carries unified session/attempt/generation correlation; the metric projection is the bounded stage×result×origin enum product and structurally cannot carry high-cardinality identity, which stays in the bounded diagnostic tail ring; `record` never blocks the caller (try-lock contention drops the event with a visible counter), so disabled statistics or slow consumers cannot affect forwarding; CLI/MCP reuse one diagnostic view via `ObserverView`); diagnostic event schema (`trace` module: `FlowTrace`/`TraceEvent` with flow/attempt/generation IDs, paired monotonic/wall clocks, evidence kinds kept distinct, major-exact schema version rule); bounded event collector (`collector` module: ring buffer, TTL, deterministic sampling, per-flow cap, visible drop counters, pull-based subscriber backpressure); diagnostic redaction boundary (`redact` module: two-scope `Redactor` — aliased export vs local detailed — with secrets stripped in both, whitelist by method set, untrusted-text sanitization); real flow lifecycle instrumentation (`session_trace` module: optional `SessionTracer` riding the authoritative session path — caller-observed takeover/identity/DNS/sniffing plus kernel-recorded rule/plan/attempts/egress/transfer/close, injected clock anchors with real measured elapsed on top, per-attempt events carrying attempt IDs, pump-measured per-direction first-byte timings, UDP mapping vs control-link reclaim as distinct lifecycle ends, and no fabricated RTT/loss without measurement); per-connection query service (`query` module: read-only paging/filtering/detail/events over the collector — list answers with honest match totals and newest first, queries are anchored on real `FlowId`s so ingress/egress aggregate keys never resolve as flows, absence is explicit per reason via bounded tombstones (unknown / evicted / expired / active-limit / sampled-out / drained / tracing-disabled) and every absent answer carries collector counters with the fixed note that no record is not evidence of no traffic) |
| `rillane-config` | Configuration models, validation, profile expansion and the config version/capability contract (`contract` module) |
| `rillane-routing` | Conditions, logical groups and routing decisions; pure Explain replay (`explain` module: rule replay over the production evaluator with frozen snapshots — no DNS/dial/OS queries, evidence gaps yield conditional results, non-deterministic strategies report the candidate pool, input digest anchors offline replay) |
| `rillane-protocols` | Inbounds, outbounds, dialing and transports |
| `rillane-runtime` | Listeners, sessions, subscriptions, TUN and Mesh assembly |
| `rillane-app` | Shared application service boundary for CLI/UI/MCP diagnostics (`RIL-065`): a closed operation set (`AppOperation` — each call maps to exactly one fixed (method, path), no generic HTTP/shell/file/admin passthrough), typed parameters validated and untrusted text sanitized before anything reaches the wire, versioned reply/error envelope decoding with explicit absence kept apart from errors, and a feature-gated blocking HTTP executor; the core depends on no MCP SDK — config reads/writes stay admin-grade outside the boundary until the proposal lifecycle (RIL-073+) |

## Capability boundaries

| Capability | Existing behavior | v1 work |
|---|---|---|
| Proxy | SOCKS5/HTTP CONNECT/mixed and multiple outbounds | Preserve standard protocols independently of optional Mesh |
| Linux TUN | TCP/UDP through shared routing with local-process annotations | Harden identity, dual-stack bypass, permissions and recovery |
| Other platforms | Build/host scaffolds; limited Android demo and private-fd iOS integration | Windows/macOS capture/identity; complete mobile forwarding/public APIs |
| Clash/Mihomo | Fetch/convert/update plumbing with partial semantics | Source replacement, providers, faithful groups/rules and strict diagnostics |
| Scenarios | Configuration-time profile defaults and separate rule-selected outbounds | Concurrent policies, resource budgets and typed quality feedback |
| Diagnostics | Aggregates, group state, Mesh dry-run and diagnose | Real flow traces, pure Explain, explicit Probe; MCP is not implemented |

RouteDecision/RoutePath already describes groups, chains and reasons; RoutePlan extends it without creating a second router. The `plan` module (RIL-006) freezes the rule result into a read-only `DecisionSnapshot`, keeps execution results (dialed/failed) separate from it, binds flows to an explicit generation via `SessionPin`, and models TCP streams and UDP datagram associations as distinct kinds. The quality sample contract (RIL-026 `quality` module) types samples with metric/source/target/count/time/validity: connection failure ratio and packet loss ratio are distinct metrics (legacy dial-sourced `packet_loss_rate` is renamed on migration), unknown/expired values error out instead of reading as zero, and packet-loss samples must state the measured peer. Subscription SHA-256 change detection exists but is not source authentication or transactional generations; the immutable `RuntimeGeneration` contract lives in `rillane-config` (RIL-003). The outbound contract (`outbound` module, RIL-097) separates establishing a channel from moving business bytes: `OpenContext` carries session/attempt/generation identity plus deadline and cancellation but holds no re-evaluable router, so an outbound makes one establishment attempt and fallback stays with the session executor; `OpenedStream`/`OpenedAssociation` own the protocol-wrapped IO and handshake result, `TargetBinding` distinguishes fixed from multi-target datagram bindings, and `OpenError` reports stage, stable code, retryability, evidence kind and redacted context. The two-phase ingress contract (`inbound` module, RIL-096) splits authentication/parsing from routing: `PendingStream` exclusively owns the client channel and a one-shot responder, success is only replied after the egress is established (a failed success reply releases the established egress inside `accept`), dropping without consuming closes the channel and never replies, UDP admission (`PendingAssociation`) pins source validation, explicit target binding and control-link reclaim, and TUN sessions carry the `Capture` origin whose replies are stack-driven instead of proxy replies. The session wiring (`session` module, RIL-098) is the one authoritative execution path over these contracts: egress establishment reuses `SessionExecutor` as the only selection implementation (fallback reconciliation lives in `attempts`, so "A failed, B dialed" stays traceable), the success reply is sent only after the egress is up, and once business bytes have been exchanged any failure ends the session as `TransferFailed` or `session.cancelled` with direction and exchanged-byte counts — never a second establishment through another egress (reconnect is a new session's new decision); the bounded-chunk pump reads one chunk and writes it before reading the next (backpressure) with TCP half-close semantics, and datagram relays validate target binding and per-datagram limits explicitly (counted rejects, no silent truncation) and reclaim on control-link closure. The dial and composition boundary (`underlay` module, RIL-099) freezes the transport-side of a legal path (VLESS over WS over TLS: dialer builds TCP → TLS → WS → protocol handshake — the order is protocol-required, not free middleware composition): the underlay dialer is the single place sockets open (DNS resolution, interface binding and bypass land there — a `DialOutcome` records honestly whether bypass was `Applied`, `NotConfigured` or `Degraded`, and degradation never masquerades as success); `TransportStack::build` checks the declared layers against an explicit grammar (raw, single `tls`/`ws`/`grpc`/`httpupgrade`, or `tls`-bottomed pairs) so illegal arrangements like `ws→tls`, duplicated layers, unknown names or native transports are assembly-time `underlay.stack.*` rejections with zero dials; `wrap_chain` applies the resolved transports in stack order and stops at the first failure (no skip, no fallback — fallback stays with the session executor), native-channel transports (`quic`, `wireguard`) refuse to wrap streams and keep their own resources, and the bypass port `PlatformBypass` makes loop-freedom injectable: adapters holding externally-opened sockets apply it via raw handle, and under a required bypass policy any `CannotInject` component (dialer or transport) is rejected at assembly with `underlay.bypass.uninjectable` instead of leaving a routing-loop hole to be discovered at dial time. The authoritative traffic accounting (`meter` module, RIL-101) puts one authoritative counter at the semantically-equivalent business-channel boundary: directions are semantic client→target / target→client (no socket read/write orientation exists in the API, so counts never flip with read vs write), partial writes add only actually-transferred bytes and fallback retries never double-count business totals, zero-length UDP still counts one datagram, and send success never claims remote receipt — the counter face has no \"remotely received\" field; attempt A's real underlay cost and its failure are recorded honestly while the business volume is attributed to carrier B exactly once, probe/prewarm origins are fixed at construction and aggregated in buckets apart from user traffic, shared multiplex overhead stays in an explicitly-marked shared bucket when precise per-flow attribution is impossible instead of fabricating per-flow precision, and ingress/egress views are attribution projections of the same authoritative volume — adding them is not usage. The session observer (`observer` module, RIL-102) carries the low-frequency stage events: ingress/establish/handshake/fallback/close all carry unified session/attempt/generation correlation (attempt-staged events without an attempt id are rejected — correlation never gets a silent default; the A-failed-B-carried reconciliation is fully explainable in the establish-failed + fallback + attempt-1 event sequence), high-frequency bytes go only to the counter — no per-read/write event is ever allocated, the metric projection is the bounded stage×result×origin enum product while session ids/domains stay in the bounded diagnostic tail ring away from metric labels, `record` uses try-lock so it never blocks forwarding (contention drops are visibly counted) and disabled statistics are a pure no-op, and CLI/MCP read one source-consistent diagnostic view via `ObserverView`. The diagnostic event schema (`trace` module, RIL-051) types real-connection traces: one `FlowTrace` per TCP session / UDP association carries a stable `FlowId`, the plan generation, and `TraceEvent`s with contiguous sequence numbers, paired monotonic/wall clocks, stable reason codes and per-event `EvidenceKind` — predicted/observed/inferred/unknown never blur into each other, `detail` must already be redacted (payload/HTTP content has no field at all), and the schema version rule is major-exact: higher majors are rejected with `trace.schema.unsupported` instead of silently degraded. The bounded collector (`collector` module, RIL-052) wraps that schema with hard resource limits: a synchronous ring buffer whose write path never awaits (full buffers evict the oldest trace with visible counters), TTL sweeping on caller-supplied clocks, deterministic counting sampling (first flow always kept, kernel adds no random source), a per-flow event cap that never drops the terminal `Close` event, and pull-based subscriber backpressure — slow readers leave closed traces parked in the ring (backlog visible in stats) and can never block the data plane; disabling tracing makes the whole collector a no-op. The real flow lifecycle instrumentation (`session_trace` module, RIL-053) rides the authoritative session path: an optional `SessionTracer` keeps the full local trace authoritative regardless of collector sampling (a sampled-out flow still gets its complete trace), records rule/plan decisions with predicted evidence, per-attempt reconciliation events that each carry the attempt ID so "A failed, B dialed" is fully explainable, the actual egress (stream established vs association mapped), pump-measured per-direction first-byte timings (HTTP TTFB and first downstream byte stay distinct), and a terminal close that distinguishes normal close from control-link reclaim — clock anchors are injected at start with real measured elapsed on top, and no RTT/loss is ever emitted without a measurement behind it. The per-connection query service (`query` module, RIL-055) is the read surface over that collector: paging and filtering of active/recent connections (honest match totals, newest first), per-flow detail and incremental event reads anchored on real `FlowId`s (ingress/egress aggregate keys never resolve as flows), and absence answers that are explicit per reason — the collector records bounded tombstones when a trace leaves it (evicted, expired, drained to subscribers, or never admitted due to active-limit/sampling), so "unknown", "gone and why", and "tracing disabled" never blur, and every absent answer ships collector counters with the fixed note that no record is not evidence of no traffic; queries are read-only snapshots and structurally cannot steal events from subscribers. The diagnostic redaction boundary (`redact` module, RIL-057) is the shared output contract for CLI/UI/MCP: every column of a diagnostic view is produced by a named `Redactor` method (the method set is the whitelist — no attach-raw-string backdoor), exports default to stable aliases for domains/paths/addresses/node names while local detailed scope widens identity fields only, and secrets never exit in either scope — subscription URLs lose credentials and token/password-style query params, PEM private-key blocks and password/token pairs in error text are replaced with placeholders, raw config blobs leave only a label and byte count, and log/subscription text is sanitized as untrusted (zero-width and control characters, length cap) in both scopes. The pure Explain service (`explain` module, RIL-054) is the "why does this flow route here" replay surface: rule/scenario matching calls the exact evaluator functions `route()` uses (no second matcher exists to drift), group state (health flags, user selections, link quality, bandwidth) is frozen into an explicit snapshot — the same (config, snapshot, input) triple replays offline to the identical conclusion; missing evidence (process annotations absent, geo databases unloaded, domain targets without DNS resolution, rule-set payloads missing, no link-quality data) is evaluated as never-matching and listed gap-by-gap, marking the conclusion conditional instead of pretending certainty; `random`/`weighted`/`round_robin` have no deterministic answer in replay — only the healthy candidate pool is reported; the whole explanation performs no DNS, no dialing and no OS identity queries, and the input SHA-256 digest ships with the conclusion for diagnostic cross-reference.

## Control and updates

Configurations carry a `version` field (currently only `1`): missing version adapts to V1 for legacy configs, and unknown versions are rejected at parse time with the stable reason code `config.version.unknown`. A build capability set (`CapabilitySet`) rejects combinations the current build cannot honor at config validation time (stable code `config.combo.unsupported`) instead of failing at dial time; the default capability set is full, so existing callers see no behavior change. The kernel `rillane-core` does not depend on `rillane-config` or Clash formats; subscription conversion stays in `rillane-subscription`.

Control uses HTTP/REST on `control.api_bind`; see [CLI reference](cli.md). `/flows` aggregates ingress/egress pairs; compatibility `/connections` maps the same aggregates with their semantics declared in the response (`rillane.view: aggregate` — the `id` is the ingress-egress pair key, not a per-flow id, and missing time/domain/rule/chains serialize as null/empty rather than fabricated values; real per-connection traces belong to the kernel query service, which this aggregate view does not replace). Diagnose bundles are scope-selected and default-safe: `safe` omits the subscription list, runtime config and full logs, `full` strips secrets on every exit (config secret keys, subscription URL credentials, log key=value pairs and PEM blocks), `raw` is unredacted and explicitly marked do-not-upload; every manifest carries the scope, a review-required file list and a manual-only upload policy — rillanectl never uploads a bundle anywhere, and bundles are not automatically safe for AI upload. The trace endpoints (`/trace/flows`, `/trace/flow`, `/trace/events`) expose the kernel's per-connection query service with a versioned envelope (`schema_version=1`) — anchored on real flow IDs, absence answered explicitly per reason; the Mesh dry-run poses as neither a rule explanation nor a per-connection trace. Trace reads carry detailed identity (domains, process names, addresses), so when `admin_token` is configured they sit behind the same permission gate as mutating endpoints (RIL-063: detailed identity is permission-controlled; a token-less local deployment stays open), and `rillanectl trace inspect <id>` is the interactive inspection entry — one boundary read rendering config attribution (generation + plan-lane events verbatim; the CLI never re-evaluates rules, replay goes through the same frozen Explain evaluator), segment expansion on the same stage→lane mapping the path graph uses (unknown stages listed explicitly), and drill-down pointers to the incremental event page and the SVG export. `POST /explain` exposes the pure Explain service over the same envelope (production evaluator over a frozen snapshot, zero side effects; input is sanitized at entry and invalid proto/domain-source values answer `explain.input.invalid`). CLI, UI and MCP consume the control plane through the shared `rillane-app` boundary (RIL-065): a closed operation set — every diagnostic call is one typed operation mapping to exactly one fixed (method, path), replies decode through the versioned envelope with explicit absence kept apart from errors, and admin-grade surfaces (raw config read, subscription URLs, config writes) stay outside the boundary. The MCP protocol and tool contract (RIL-066) is frozen in the same crate, no SDK involved: the protocol version is pinned to the official modern-era revision 2026-07-28 (per-request version declaration in `params._meta` with `UnsupportedProtocolVersionError` -32022 answers, mandatory `server/discover`, cancellation via `notifications/cancelled` — stop, free resources, do not answer), the tool catalog is the same closed 16-tool set with typed input schemas that reject unknown fields and oversize arguments before dispatch, and tool annotations are structurally hint-only fields kept apart from the server-side authorization scopes the adapter enforces (annotations are never authority — the stdio server itself lands with RIL-067). Server-side scope enforcement (RIL-068) gates every `tools/call` before validation and execution: the granted scope set comes only from startup configuration (default read-only — minimal surface), authorization reads the frozen catalog's server-side scope field (never annotations, never any request-declared authorization claim — a directly crafted call carrying `scope`/`granted`/`authorized` fields cannot escalate), denials answer the stable code -32001 (`mcp.scope.denied` with the required scope name) without executing or consuming rate quota, and a fixed-window rate limiter (default 60 calls per minute, `--rate-limit 0` to disable) answers -32002 (`mcp.rate.limited`) for calls past the window; credentials stay in the adapter's executor and never appear in replies or logs. The status and quality tools (RIL-069) serve the same daemon payloads the CLI consumes — answers carry the envelope verbatim (sample freshness expressed by the member `source` field real/legacy/unknown, missing samples as explicit nulls, never zero-filled) — and every tool answer passes a response-size gate (`MAX_RESULT_BYTES`, 256 KiB): oversized payloads answer in-band with `mcp.result.oversize` (byte counts only — no payload echo, no truncated JSON), and a token-leak regression asserts the admin token never appears in any answer on the success or failure path. The connection and Explain tools (RIL-070) are pinned end-to-end: paging/filter parameters reach the daemon query string verbatim, envelopes pass through byte-faithful (plan generation and per-event evidence kinds preserved — predicted/observed never blur), one tools/call issues exactly one boundary read (a capturing one-shot server makes any implicit second request time out the test), and the Explain tool stays a zero-side-effect replay whose conditional conclusion, evidence gaps and input digest pass through unmodified — queries cannot implicitly grow collection or issue extra network requests, and every answer stays under the RIL-069 byte cap. Active probing (RIL-071) ships with its own authorization and quota face: submit/cancel sit behind the probe scope (a read-only session is refused before execution — `-32001`, no boundary request), every job the session submits is tracked against its request, and release is structural — a cancelled call (whether the cancel lands before or after the answer) triggers a best-effort `POST /probe/cancel` for the job, an explicit cancel success drops the tracking, and EOF exit releases everything still outstanding, so no probe outlives its session or stays unowned; targets are never pre-approved client-side — the arbitrary/intranet-target rejection (`probe.target.out_of_scope`) and the budget wall (`probe.limit.budget`) are daemon policy answers passed through verbatim, and a rejected submit creates no job. Untrusted-content and leak regressions (RIL-072) pin the remaining faces: daemon payload strings carrying zero-width characters, CRLF, ANSI escapes and JSON-RPC-shaped text travel only as data (serialization stays one line — a payload cannot become a second protocol instruction, and later protocol lines are unaffected); boundary-call arguments cannot inject requests (control characters are sanitized at the ops layer and query values are percent-encoded at the executor — shared with the CLI — so `&`, `#`, `?`, spaces and `%` cannot become parameter separators or a new request line); oversized daemon payloads answer with the bounded `mcp.result.oversize` envelope without echo; and the detailed-identity tier neither opens the probe gate (still `-32001`, no request echo in the denial data) nor changes secrecy on failure paths (no credentials in any answer).

The config transaction closure (RIL-079) gives CLI and MCP one door: the daemon-side `ConfigTxService` assembles the pure proposal/approval/apply/rollback faces (RIL-073–077) behind `POST /config/proposals`, `/config/rollback-proposal`, `/config/preview`, `/config/approve`, `/config/apply`, `/config/rollback` and the read side `GET /config/state`, `/config/receipts`. The daemon fills the base generation, live content digest and rollback candidate identity itself — a client cannot state the live face and therefore cannot bypass the version/content prechecks (`apply.base.conflict` / `apply.hash.conflict` answer as 409 stable-code envelopes). Approvals are real operator decisions: a credential binds the proposal digest, owner, scope and TTL and is consumed exactly once — the daemon never self-approves; rollback proposals carry a marker scope so the forward and rollback paths cannot impersonate each other, and reusing an idempotency key under a different identity is refused (`apply.key.mismatch`). The forward executor merges the patch (RFC 7396), deserializes, validates against the capability set and rotates the live face; the retired content enters a bounded history that the rollback executor restores from (an out-of-history candidate answers explicitly instead of pretending). `GET /config/receipts` reports the receipt chain (seq desc) reconciled against the daemon's own live face — OS-side execution wiring stays with the publish-coordinator work (RIL-019/081+), and `os_applied` on this face means the daemon's config-content and generation ledgers landed. All write endpoints sit behind the `admin_token` gate when configured, and the `config` CLI subcommands walk the same endpoints with no local bypass. The MCP proposal tools (RIL-080) extend the frozen catalog to 13 entries over the same door: `validate_config` (read scope) is a single `POST /config/preview` read-only projection — redacted diff, diagnostics and scope violations, no proposal, nothing activates; `preview_config_change` (write scope) registers a proposal through `POST /config/proposals` and returns the server-side proposal ID, base generation, expiry and the exact proposal-time preview (computed under the same lock as registration — the diff is the admission basis, not a post-hoc approximation). The proposal answer never echoes the patch (the caller supplied it; large patches do not occupy the answer and secret values gain no extra copy), and the adapter fixes the proposal owner to `mcp` — the model-facing schema has no owner field (`additionalProperties:false` rejects it), so impersonating another owner is structurally impossible; approval and apply stay outside the tool surface (operator decisions through CLI or dedicated authorization), so a read-only session cannot use preview to activate anything: the answer is a projection, and the only path from preview to activation crosses an explicit approval gate the tools do not reach. Config endpoint replies carry the versioned envelope (`schema_version=1`, fields kept flat — CLI consumers unaffected), and the secret redaction of preview answers was verified end-to-end through the tool (a patch touching `control.admin_token` answers `[redacted]` on both sides of the diff). The MCP apply and rollback tools (RIL-081) close the loop without ever opening an arbitrary admin-API escape hatch: `apply_config_change` (write scope) consumes operator-issued credentials only — the schema requires both the proposal ID and the approval ID the daemon signed, the adapter pins the apply owner to `mcp` so credentials issued for other owners structurally cannot be spent here, and the idempotency key is derived deterministically from the two IDs (`mcp-{proposal_id}-{approval_id}`) unless supplied, so a repeated call replays the same receipt (`phase: replayed`) instead of double-executing; `rollback_config` is two-phase — with no credentials it registers a daemon-built rollback proposal through `POST /config/rollback-proposal` (target receipt must be on the ledger, `Applied` and owned by `mcp`), and with both credentials present it executes through `POST /config/rollback` under a rollback-specific key prefix (`mcp-rb-…`), while exactly one of the two IDs is an invalid input answered before any boundary request (a half-credential is not an authorization face); `config_audit` (read scope) reads the receipt chain with its reconcile verdict, so a read-only session can verify what changed and what the live face agrees with; live end-to-end the cycle propose → operator approve (`rillanectl config approve --owner mcp`) → apply → replay → audit → rollback prepare → operator approve → rollback execute restored the original generation with the drain deadline honored and existing connections honestly reported as pinned (no claimed connection restoration).

`rillaned` loads `RILLANE_CONFIG` at startup. There is no general file watch, SIGHUP reload or `rillanectl reload`. Existing subscription/control updates are not v1 cross-OS transactions. The side-effect contract for route/DNS/firewall changes (`side_effects`: journal, ownership records, idempotent undo — only this instance's entries are undone; pre-existing system config is recorded, never reverted) is in place; Linux-side execution wiring lands with the config publish coordinator (RIL-019). See [verified gaps](research/proxy-architectures-2026-11-14.md#verified-gaps) for append-only merging, group semantics and interval units.
