# Current implementation and boundaries

This is an implementation reference, not another architecture design. The **single current design baseline is [v1 architecture](design/architecture-v1.md)**, supported by [concepts](design/architecture-concepts.md) and [Debug/MCP](design/debug-and-mcp.md). Those targets are not implemented as a whole.

## Code organization

| Directory/module | Current responsibility |
|---|---|
| `apps/rillaned` | Configuration, runtime assembly and HTTP control plane |
| `apps/rillanectl` | Configuration utilities, control queries, subscriptions and certificates |
| `rillane-core` | Flow/FlowContext, RouteDecision/RoutePath, forwarding and UDP contracts; flow/plan/session contracts (`plan` module: one-way RoutePlan mapping, SessionPin, TCP/UDP association boundary); two-phase ingress contracts (`inbound` module: `InboundSpec`/`InboundFactory`, `PendingStream`/`PendingAssociation` with one-shot responders, capture origin for TUN); outbound establishment contracts (`outbound` module: `StreamOutbound`/`DatagramOutbound`, `OpenContext`, opened stream/association, staged `OpenError`); session executor wiring (`session` module: one authoritative accept→establish→reply→pump path, no replay after business exchange); diagnostic event schema (`trace` module: `FlowTrace`/`TraceEvent` with flow/attempt/generation IDs, paired monotonic/wall clocks, evidence kinds kept distinct, major-exact schema version rule); bounded event collector (`collector` module: ring buffer, TTL, deterministic sampling, per-flow cap, visible drop counters, pull-based subscriber backpressure); diagnostic redaction boundary (`redact` module: two-scope `Redactor` — aliased export vs local detailed — with secrets stripped in both, whitelist by method set, untrusted-text sanitization) |
| `rillane-config` | Configuration models, validation, profile expansion and the config version/capability contract (`contract` module) |
| `rillane-routing` | Conditions, logical groups and routing decisions |
| `rillane-protocols` | Inbounds, outbounds, dialing and transports |
| `rillane-runtime` | Listeners, sessions, subscriptions, TUN and Mesh assembly |
| `rillane-platform` | Capture, route/DNS models and Linux integration; side-effect journal and ownership-undo contract (`side_effects` module) |
| `rillane-subscription` | Fetch, detect, convert, cache, digest and refresh |
| `rillane-mesh` / `rillane-plugins` | Managed topology and WASM middleware; plugins are optional behind the runtime `plugins` feature (RIL-040: `full` default, `small`/`mobile` builds carry no Wasmtime) |
| `rillane-telemetry` / `rillane-ffi` | Logging and mobile FFI foundations |
| `platforms/` | Hosts, installers and packages; scaffolding is not runtime acceptance |

## Capability boundaries

| Capability | Existing behavior | v1 work |
|---|---|---|
| Proxy | SOCKS5/HTTP CONNECT/mixed and multiple outbounds | Preserve standard protocols independently of optional Mesh |
| Linux TUN | TCP/UDP through shared routing with local-process annotations | Harden identity, dual-stack bypass, permissions and recovery |
| Other platforms | Build/host scaffolds; limited Android demo and private-fd iOS integration | Windows/macOS capture/identity; complete mobile forwarding/public APIs |
| Clash/Mihomo | Fetch/convert/update plumbing with partial semantics | Source replacement, providers, faithful groups/rules and strict diagnostics |
| Scenarios | Configuration-time profile defaults and separate rule-selected outbounds | Concurrent policies, resource budgets and typed quality feedback |
| Diagnostics | Aggregates, group state, Mesh dry-run and diagnose | Real flow traces, pure Explain, explicit Probe; MCP is not implemented |

RouteDecision/RoutePath already describes groups, chains and reasons; RoutePlan extends it without creating a second router. The `plan` module (RIL-006) freezes the rule result into a read-only `DecisionSnapshot`, keeps execution results (dialed/failed) separate from it, binds flows to an explicit generation via `SessionPin`, and models TCP streams and UDP datagram associations as distinct kinds. The quality sample contract (RIL-026 `quality` module) types samples with metric/source/target/count/time/validity: connection failure ratio and packet loss ratio are distinct metrics (legacy dial-sourced `packet_loss_rate` is renamed on migration), unknown/expired values error out instead of reading as zero, and packet-loss samples must state the measured peer. Subscription SHA-256 change detection exists but is not source authentication or transactional generations; the immutable `RuntimeGeneration` contract lives in `rillane-config` (RIL-003). The outbound contract (`outbound` module, RIL-097) separates establishing a channel from moving business bytes: `OpenContext` carries session/attempt/generation identity plus deadline and cancellation but holds no re-evaluable router, so an outbound makes one establishment attempt and fallback stays with the session executor; `OpenedStream`/`OpenedAssociation` own the protocol-wrapped IO and handshake result, `TargetBinding` distinguishes fixed from multi-target datagram bindings, and `OpenError` reports stage, stable code, retryability, evidence kind and redacted context. The two-phase ingress contract (`inbound` module, RIL-096) splits authentication/parsing from routing: `PendingStream` exclusively owns the client channel and a one-shot responder, success is only replied after the egress is established (a failed success reply releases the established egress inside `accept`), dropping without consuming closes the channel and never replies, UDP admission (`PendingAssociation`) pins source validation, explicit target binding and control-link reclaim, and TUN sessions carry the `Capture` origin whose replies are stack-driven instead of proxy replies. The session wiring (`session` module, RIL-098) is the one authoritative execution path over these contracts: egress establishment reuses `SessionExecutor` as the only selection implementation (fallback reconciliation lives in `attempts`, so "A failed, B dialed" stays traceable), the success reply is sent only after the egress is up, and once business bytes have been exchanged any failure ends the session as `TransferFailed` or `session.cancelled` with direction and exchanged-byte counts — never a second establishment through another egress (reconnect is a new session's new decision); the bounded-chunk pump reads one chunk and writes it before reading the next (backpressure) with TCP half-close semantics, and datagram relays validate target binding and per-datagram limits explicitly (counted rejects, no silent truncation) and reclaim on control-link closure. The diagnostic event schema (`trace` module, RIL-051) types real-connection traces: one `FlowTrace` per TCP session / UDP association carries a stable `FlowId`, the plan generation, and `TraceEvent`s with contiguous sequence numbers, paired monotonic/wall clocks, stable reason codes and per-event `EvidenceKind` — predicted/observed/inferred/unknown never blur into each other, `detail` must already be redacted (payload/HTTP content has no field at all), and the schema version rule is major-exact: higher majors are rejected with `trace.schema.unsupported` instead of silently degraded. The bounded collector (`collector` module, RIL-052) wraps that schema with hard resource limits: a synchronous ring buffer whose write path never awaits (full buffers evict the oldest trace with visible counters), TTL sweeping on caller-supplied clocks, deterministic counting sampling (first flow always kept, kernel adds no random source), a per-flow event cap that never drops the terminal `Close` event, and pull-based subscriber backpressure — slow readers leave closed traces parked in the ring (backlog visible in stats) and can never block the data plane; disabling tracing makes the whole collector a no-op. The diagnostic redaction boundary (`redact` module, RIL-057) is the shared output contract for CLI/UI/MCP: every column of a diagnostic view is produced by a named `Redactor` method (the method set is the whitelist — no attach-raw-string backdoor), exports default to stable aliases for domains/paths/addresses/node names while local detailed scope widens identity fields only, and secrets never exit in either scope — subscription URLs lose credentials and token/password-style query params, PEM private-key blocks and password/token pairs in error text are replaced with placeholders, raw config blobs leave only a label and byte count, and log/subscription text is sanitized as untrusted (zero-width and control characters, length cap) in both scopes.

## Control and updates

Configurations carry a `version` field (currently only `1`): missing version adapts to V1 for legacy configs, and unknown versions are rejected at parse time with the stable reason code `config.version.unknown`. A build capability set (`CapabilitySet`) rejects combinations the current build cannot honor at config validation time (stable code `config.combo.unsupported`) instead of failing at dial time; the default capability set is full, so existing callers see no behavior change. The kernel `rillane-core` does not depend on `rillane-config` or Clash formats; subscription conversion stays in `rillane-subscription`.

Control uses HTTP/REST on `control.api_bind`; see [CLI reference](cli.md). `/flows` aggregates ingress/egress pairs; compatibility `/connections` is not a complete real connection table. Diagnose bundles may contain sensitive runtime information and are not automatically safe for AI upload.

`rillaned` loads `RILLANE_CONFIG` at startup. There is no general file watch, SIGHUP reload or `rillanectl reload`. Existing subscription/control updates are not v1 cross-OS transactions. The side-effect contract for route/DNS/firewall changes (`side_effects`: journal, ownership records, idempotent undo — only this instance's entries are undone; pre-existing system config is recorded, never reverted) is in place; Linux-side execution wiring lands with the config publish coordinator (RIL-019). See [verified gaps](research/proxy-architectures-2026-11-14.md#verified-gaps) for append-only merging, group semantics and interval units.
