# Current implementation and boundaries

This is an implementation reference, not another architecture design. The **single current design baseline is [v1 architecture](design/architecture-v1.md)**, supported by [concepts](design/architecture-concepts.md) and [Debug/MCP](design/debug-and-mcp.md). Those targets are not implemented as a whole.

## Code organization

| Directory/module | Current responsibility |
|---|---|
| `apps/rillaned` | Configuration, runtime assembly and HTTP control plane |
| `apps/rillanectl` | Configuration utilities, control queries, subscriptions and certificates |
| `apps/rillane-mcp` | Optional stdio MCP adapter (`RIL-067`): off by default, no listener port — an explicit-start client of the control plane over the shared `rillane-app` boundary; stdout carries protocol messages only (one JSON-RPC message per line, official 2026-07-28 modern-era contract with per-request version gates, `server/discover` and cancellation suppression), logs go to stderr, bounded per-request execution (30 s cap), EOF exits cleanly leaving no background work (probe jobs live daemon-side under server quotas); session authorization scopes come only from startup flags (default read-only, `RIL-068`) with a fixed-window per-minute tool-call rate limit |
| `rillane-core` | Flow/FlowContext, RouteDecision/RoutePath, forwarding and UDP contracts; flow/plan/session contracts (`plan` module: one-way RoutePlan mapping, SessionPin, TCP/UDP association boundary); two-phase ingress contracts (`inbound` module: `InboundSpec`/`InboundFactory`, `PendingStream`/`PendingAssociation` with one-shot responders, capture origin for TUN); outbound establishment contracts (`outbound` module: `StreamOutbound`/`DatagramOutbound`, `OpenContext`, opened stream/association, staged `OpenError`); session executor wiring (`session` module: one authoritative accept→establish→reply→pump path, no replay after business exchange); diagnostic event schema (`trace` module: `FlowTrace`/`TraceEvent` with flow/attempt/generation IDs, paired monotonic/wall clocks, evidence kinds kept distinct, major-exact schema version rule); bounded event collector (`collector` module: ring buffer, TTL, deterministic sampling, per-flow cap, visible drop counters, pull-based subscriber backpressure); diagnostic redaction boundary (`redact` module: two-scope `Redactor` — aliased export vs local detailed — with secrets stripped in both, whitelist by method set, untrusted-text sanitization); real flow lifecycle instrumentation (`session_trace` module: optional `SessionTracer` riding the authoritative session path — caller-observed takeover/identity/DNS/sniffing plus kernel-recorded rule/plan/attempts/egress/transfer/close, injected clock anchors with real measured elapsed on top, per-attempt events carrying attempt IDs, pump-measured per-direction first-byte timings, UDP mapping vs control-link reclaim as distinct lifecycle ends, and no fabricated RTT/loss without measurement); per-connection query service (`query` module: read-only paging/filtering/detail/events over the collector — list answers with honest match totals and newest first, queries are anchored on real `FlowId`s so ingress/egress aggregate keys never resolve as flows, absence is explicit per reason via bounded tombstones (unknown / evicted / expired / active-limit / sampled-out / drained / tracing-disabled) and every absent answer carries collector counters with the fixed note that no record is not evidence of no traffic) |
| `rillane-config` | Configuration models, validation, profile expansion and the config version/capability contract (`contract` module) |
| `rillane-routing` | Conditions, logical groups and routing decisions; pure Explain replay (`explain` module: rule replay over the production evaluator with frozen snapshots — no DNS/dial/OS queries, evidence gaps yield conditional results, non-deterministic strategies report the candidate pool, input digest anchors offline replay) |
| `rillane-protocols` | Inbounds, outbounds, dialing and transports |
| `rillane-runtime` | Listeners, sessions, subscriptions, TUN and Mesh assembly |
| `rillane-app` | Shared application service boundary for CLI/UI/MCP diagnostics (`RIL-065`): a closed operation set (`AppOperation` — each call maps to exactly one fixed (method, path), no generic HTTP/shell/file/admin passthrough), typed parameters validated and untrusted text sanitized before anything reaches the wire, versioned reply/error envelope decoding with explicit absence kept apart from errors, and a feature-gated blocking HTTP executor; the core depends on no MCP SDK — config reads/writes stay admin-grade outside the boundary until the proposal lifecycle (RIL-073+) |

| `platforms/` | Hosts, installers and packages; scaffolding is not runtime acceptance |

## Capability boundaries

| Capability | Existing behavior | v1 work |
|---|---|---|
| Proxy | SOCKS5/HTTP CONNECT/mixed and multiple outbounds | Preserve standard protocols independently of optional Mesh |
| Linux TUN | TCP/UDP through shared routing with local-process annotations | Harden identity, dual-stack bypass, permissions and recovery |
| Other platforms | Build/host scaffolds; limited Android demo and private-fd iOS integration | Windows/macOS capture/identity; complete mobile forwarding/public APIs |
| Clash/Mihomo | Fetch/convert/update plumbing with partial semantics | Source replacement, providers, faithful groups/rules and strict diagnostics |
| Scenarios | Configuration-time profile defaults and separate rule-selected outbounds | Concurrent policies, resource budgets and typed quality feedback |
| Diagnostics | Aggregates, group state, Mesh dry-run and diagnose | Real flow traces, pure Explain, explicit Probe; MCP is not implemented |

RouteDecision/RoutePath already describes groups, chains and reasons; RoutePlan extends it without creating a second router. The `plan` module (RIL-006) freezes the rule result into a read-only `DecisionSnapshot`, keeps execution results (dialed/failed) separate from it, binds flows to an explicit generation via `SessionPin`, and models TCP streams and UDP datagram associations as distinct kinds. The quality sample contract (RIL-026 `quality` module) types samples with metric/source/target/count/time/validity: connection failure ratio and packet loss ratio are distinct metrics (legacy dial-sourced `packet_loss_rate` is renamed on migration), unknown/expired values error out instead of reading as zero, and packet-loss samples must state the measured peer. Subscription SHA-256 change detection exists but is not source authentication or transactional generations; the immutable `RuntimeGeneration` contract lives in `rillane-config` (RIL-003). The outbound contract (`outbound` module, RIL-097) separates establishing a channel from moving business bytes: `OpenContext` carries session/attempt/generation identity plus deadline and cancellation but holds no re-evaluable router, so an outbound makes one establishment attempt and fallback stays with the session executor; `OpenedStream`/`OpenedAssociation` own the protocol-wrapped IO and handshake result, `TargetBinding` distinguishes fixed from multi-target datagram bindings, and `OpenError` reports stage, stable code, retryability, evidence kind and redacted context. The two-phase ingress contract (`inbound` module, RIL-096) splits authentication/parsing from routing: `PendingStream` exclusively owns the client channel and a one-shot responder, success is only replied after the egress is established (a failed success reply releases the established egress inside `accept`), dropping without consuming closes the channel and never replies, UDP admission (`PendingAssociation`) pins source validation, explicit target binding and control-link reclaim, and TUN sessions carry the `Capture` origin whose replies are stack-driven instead of proxy replies. The session wiring (`session` module, RIL-098) is the one authoritative execution path over these contracts: egress establishment reuses `SessionExecutor` as the only selection implementation (fallback reconciliation lives in `attempts`, so "A failed, B dialed" stays traceable), the success reply is sent only after the egress is up, and once business bytes have been exchanged any failure ends the session as `TransferFailed` or `session.cancelled` with direction and exchanged-byte counts — never a second establishment through another egress (reconnect is a new session's new decision); the bounded-chunk pump reads one chunk and writes it before reading the next (backpressure) with TCP half-close semantics, and datagram relays validate target binding and per-datagram limits explicitly (counted rejects, no silent truncation) and reclaim on control-link closure. The diagnostic event schema (`trace` module, RIL-051) types real-connection traces: one `FlowTrace` per TCP session / UDP association carries a stable `FlowId`, the plan generation, and `TraceEvent`s with contiguous sequence numbers, paired monotonic/wall clocks, stable reason codes and per-event `EvidenceKind` — predicted/observed/inferred/unknown never blur into each other, `detail` must already be redacted (payload/HTTP content has no field at all), and the schema version rule is major-exact: higher majors are rejected with `trace.schema.unsupported` instead of silently degraded. The bounded collector (`collector` module, RIL-052) wraps that schema with hard resource limits: a synchronous ring buffer whose write path never awaits (full buffers evict the oldest trace with visible counters), TTL sweeping on caller-supplied clocks, deterministic counting sampling (first flow always kept, kernel adds no random source), a per-flow event cap that never drops the terminal `Close` event, and pull-based subscriber backpressure — slow readers leave closed traces parked in the ring (backlog visible in stats) and can never block the data plane; disabling tracing makes the whole collector a no-op. The real flow lifecycle instrumentation (`session_trace` module, RIL-053) rides the authoritative session path: an optional `SessionTracer` keeps the full local trace authoritative regardless of collector sampling (a sampled-out flow still gets its complete trace), records rule/plan decisions with predicted evidence, per-attempt reconciliation events that each carry the attempt ID so "A failed, B dialed" is fully explainable, the actual egress (stream established vs association mapped), pump-measured per-direction first-byte timings (HTTP TTFB and first downstream byte stay distinct), and a terminal close that distinguishes normal close from control-link reclaim — clock anchors are injected at start with real measured elapsed on top, and no RTT/loss is ever emitted without a measurement behind it. The per-connection query service (`query` module, RIL-055) is the read surface over that collector: paging and filtering of active/recent connections (honest match totals, newest first), per-flow detail and incremental event reads anchored on real `FlowId`s (ingress/egress aggregate keys never resolve as flows), and absence answers that are explicit per reason — the collector records bounded tombstones when a trace leaves it (evicted, expired, drained to subscribers, or never admitted due to active-limit/sampling), so "unknown", "gone and why", and "tracing disabled" never blur, and every absent answer ships collector counters with the fixed note that no record is not evidence of no traffic; queries are read-only snapshots and structurally cannot steal events from subscribers. The diagnostic redaction boundary (`redact` module, RIL-057) is the shared output contract for CLI/UI/MCP: every column of a diagnostic view is produced by a named `Redactor` method (the method set is the whitelist — no attach-raw-string backdoor), exports default to stable aliases for domains/paths/addresses/node names while local detailed scope widens identity fields only, and secrets never exit in either scope — subscription URLs lose credentials and token/password-style query params, PEM private-key blocks and password/token pairs in error text are replaced with placeholders, raw config blobs leave only a label and byte count, and log/subscription text is sanitized as untrusted (zero-width and control characters, length cap) in both scopes. The pure Explain service (`explain` module, RIL-054) is the "why does this flow route here" replay surface: rule/scenario matching calls the exact evaluator functions `route()` uses (no second matcher exists to drift), group state (health flags, user selections, link quality, bandwidth) is frozen into an explicit snapshot — the same (config, snapshot, input) triple replays offline to the identical conclusion; missing evidence (process annotations absent, geo databases unloaded, domain targets without DNS resolution, rule-set payloads missing, no link-quality data) is evaluated as never-matching and listed gap-by-gap, marking the conclusion conditional instead of pretending certainty; `random`/`weighted`/`round_robin` have no deterministic answer in replay — only the healthy candidate pool is reported; the whole explanation performs no DNS, no dialing and no OS identity queries, and the input SHA-256 digest ships with the conclusion for diagnostic cross-reference.

## Control and updates

Configurations carry a `version` field (currently only `1`): missing version adapts to V1 for legacy configs, and unknown versions are rejected at parse time with the stable reason code `config.version.unknown`. A build capability set (`CapabilitySet`) rejects combinations the current build cannot honor at config validation time (stable code `config.combo.unsupported`) instead of failing at dial time; the default capability set is full, so existing callers see no behavior change. The kernel `rillane-core` does not depend on `rillane-config` or Clash formats; subscription conversion stays in `rillane-subscription`.

Control uses HTTP/REST on `control.api_bind`; see [CLI reference](cli.md). `/flows` aggregates ingress/egress pairs; compatibility `/connections` maps the same aggregates with their semantics declared in the response (`rillane.view: aggregate` — the `id` is the ingress-egress pair key, not a per-flow id, and missing time/domain/rule/chains serialize as null/empty rather than fabricated values; real per-connection traces belong to the kernel query service, which this aggregate view does not replace). Diagnose bundles are scope-selected and default-safe: `safe` omits the subscription list, runtime config and full logs, `full` strips secrets on every exit (config secret keys, subscription URL credentials, log key=value pairs and PEM blocks), `raw` is unredacted and explicitly marked do-not-upload; every manifest carries the scope, a review-required file list and a manual-only upload policy — rillanectl never uploads a bundle anywhere, and bundles are not automatically safe for AI upload. The trace endpoints (`/trace/flows`, `/trace/flow`, `/trace/events`) expose the kernel's per-connection query service with a versioned envelope (`schema_version=1`) — anchored on real flow IDs, absence answered explicitly per reason; the Mesh dry-run poses as neither a rule explanation nor a per-connection trace. `POST /explain` exposes the pure Explain service over the same envelope (production evaluator over a frozen snapshot, zero side effects; input is sanitized at entry and invalid proto/domain-source values answer `explain.input.invalid`). CLI, UI and MCP consume the control plane through the shared `rillane-app` boundary (RIL-065): a closed operation set — every diagnostic call is one typed operation mapping to exactly one fixed (method, path), replies decode through the versioned envelope with explicit absence kept apart from errors, and admin-grade surfaces (raw config read, subscription URLs, config writes) stay outside the boundary. The MCP protocol and tool contract (RIL-066) is frozen in the same crate, no SDK involved: the protocol version is pinned to the official modern-era revision 2026-07-28 (per-request version declaration in `params._meta` with `UnsupportedProtocolVersionError` -32022 answers, mandatory `server/discover`, cancellation via `notifications/cancelled` — stop, free resources, do not answer), the tool catalog is the same closed 11-operation set with typed input schemas that reject unknown fields and oversize arguments before dispatch, and tool annotations are structurally hint-only fields kept apart from the server-side authorization scopes the adapter enforces (annotations are never authority — the stdio server itself lands with RIL-067). Server-side scope enforcement (RIL-068) gates every `tools/call` before validation and execution: the granted scope set comes only from startup configuration (default read-only — minimal surface), authorization reads the frozen catalog's server-side scope field (never annotations, never any request-declared authorization claim — a directly crafted call carrying `scope`/`granted`/`authorized` fields cannot escalate), denials answer the stable code -32001 (`mcp.scope.denied` with the required scope name) without executing or consuming rate quota, and a fixed-window rate limiter (default 60 calls per minute, `--rate-limit 0` to disable) answers -32002 (`mcp.rate.limited`) for calls past the window; credentials stay in the adapter's executor and never appear in replies or logs. The status and quality tools (RIL-069) serve the same daemon payloads the CLI consumes — answers carry the envelope verbatim (sample freshness expressed by the member `source` field real/legacy/unknown, missing samples as explicit nulls, never zero-filled) — and every tool answer passes a response-size gate (`MAX_RESULT_BYTES`, 256 KiB): oversized payloads answer in-band with `mcp.result.oversize` (byte counts only — no payload echo, no truncated JSON), and a token-leak regression asserts the admin token never appears in any answer on the success or failure path. The connection and Explain tools (RIL-070) are pinned end-to-end: paging/filter parameters reach the daemon query string verbatim, envelopes pass through byte-faithful (plan generation and per-event evidence kinds preserved — predicted/observed never blur), one tools/call issues exactly one boundary read (a capturing one-shot server makes any implicit second request time out the test), and the Explain tool stays a zero-side-effect replay whose conditional conclusion, evidence gaps and input digest pass through unmodified — queries cannot implicitly grow collection or issue extra network requests, and every answer stays under the RIL-069 byte cap.

`rillaned` loads `RILLANE_CONFIG` at startup. There is no general file watch, SIGHUP reload or `rillanectl reload`. Existing subscription/control updates are not v1 cross-OS transactions. The side-effect contract for route/DNS/firewall changes (`side_effects`: journal, ownership records, idempotent undo — only this instance's entries are undone; pre-existing system config is recorded, never reverted) is in place; Linux-side execution wiring lands with the config publish coordinator (RIL-019). See [verified gaps](research/proxy-architectures-2026-11-14.md#verified-gaps) for append-only merging, group semantics and interval units.
