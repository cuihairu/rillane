# 当前实现与边界

本页是现有代码的实现参考，不是另一版架构设计。**当前唯一设计基线是 [v1 架构设计](design/architecture-v1.md)**，配套[概念说明](design/architecture-concepts.md)与 [Debug / MCP](design/debug-and-mcp.md)；这些目标尚未整体实现。

## 代码组织

| 目录/模块 | 当前职责 |
|---|---|
| `apps/rillaned` | 配置加载、运行时装配、HTTP 控制面 |
| `apps/rillanectl` | 配置工具、控制面查询、订阅与证书管理 |
| `apps/rillane-mcp` | 可选 stdio MCP 适配器（RIL-067）：默认不启用、不监听任何端口——显式启动的控制面客户端，经共享 `rillane-app` 边界出站访问守护进程；stdout 只走协议（一行一条 JSON-RPC，官方 2026-07-28 modern era 契约：逐请求版本门、`server/discover`、取消后不答复），日志走 stderr，单请求限时（30 s 上限），EOF 干净退出、不遗留后台作业（探测作业在守护进程侧配额管束）；会话授权档只来自启动参数（默认只读，RIL-068），带每分钟固定窗工具调用限速 |
| `rillane-core` | Flow、FlowContext、RouteDecision/RoutePath、转发接口与 UDP 基础类型；流/计划/会话契约（`plan` 模块：RoutePlan 单向映射、SessionPin、TCP/UDP 绑定边界）；入口两阶段接入契约（`inbound` 模块：`InboundSpec`/`InboundFactory`、一次性 模块：接入确认→出口建立→成功回复→双向泵送的一条权威路径，业务交换后不重放）；能力装配与池资源类型（`resources` 模块：`assemble_backend` 是支持表的唯一权威——声明的能力表、传输栈、复用类与 feature 门在装配期一次合并校验，importer/runtime/connector 消费同一份 `AssembledBackend`、不各自维护支持表；池资源类型化为预热消费 / 独占目标绑定 / 多路复用会话，`LeaseKey` 携带代际/节点/目标/凭证/安全配置标签——不同租户、凭证或代际结构性不混借，`LeaseGuard` 是消费/排水/取消/关闭迁移的唯一所有者句柄；TLS 会话恢复与连接复用是不同资源——恢复要求栈内有 `tls` 且与多路复用互斥）；底层拨号与传输组合契约（`underlay` 模块：`UnderlayDialer` 是唯一开 socket 的入口——DNS、接口绑定与平台旁路都在原始 socket 打开时施加，传输层拿到的永远是已连接流，DNS/旁路逻辑结构上无处复制；`TransportStack` 以显式语法表在装配期校验 TLS/WS/gRPC/HTTPUpgrade 排列——非法排列静态拒绝；QUIC/WireGuard 是 `TransportClass::NativeChannel`、持有原生资源，不被强制转换为普通字节流 wrapper；`PlatformBypass::apply_raw` 经原始句柄向外部库自建 socket 注入旁路，旁路必选策略下声明 `CannotInject` 的组件装配期即拒——无法注入即无法保证防环）；权威业务计数（`meter` 模块：`SessionMeter` 是业务通道边界的唯一权威计数器——方向按客户端→目标/目标→客户端语义定义、不随 socket 读写翻转；部分写只累加实际过账字节、回退重试不重复业务总量，零长 UDP 仍计一条报文；底层加密/握手开销与共享多路复用公共开销是分立字段、不并入业务——共享开销不可精确归因时显式标记，不伪造每流精度；A 失败 B 承载只计一次业务量、承载归属恰一次；`TrafficOrigin` 在构造期分类，probe/prewarm 与用户业务分桶汇总互不吸收；入口/出口是同一业务量的归属投影——相加不是总使用量）；会话观测器（`observer` 模块：接入/建立/握手/回退/关闭等低频阶段事件面——高频字节走 `SessionMeter` 计数器，不为每次读写分配事件；每条事件统一携带 session/attempt/generation 关联；指标投影是 stage×result×origin 有界枚举积、结构上无法携带高基数身份，session_id/域名只留有界诊断尾环；`record` 永不阻塞调用方（try_lock 争用即丢弃并计数可见），统计关闭（容量 0）或慢消费者都不影响转发；CLI/MCP 经同一 `ObserverView` 复用诊断视图）；诊断事件 Schema（`trace` 模块：`FlowTrace`/`TraceEvent`，flow/attempt/generation ID、成对单调/墙钟、证据类型分立、主版本精确的 schema 兼容规则）；有界事件采集器（`collector` 模块：环形缓冲、TTL、确定性采样、每流上限、可见丢事件计数、拉式订阅背压）；诊断脱敏边界（`redact` 模块：两档 `Redactor`——导出别名档 vs 本机详细档，秘密两档都剥除、白名单即方法集、不可信文本消毒）；真实流生命周期埋点（`session_trace` 模块：可选 `SessionTracer` `FlowId` 为锚、ingress/egress 聚合键不会命中任何流，缺席经有界墓碑逐码显式（unknown/evicted/expired/active_limit/sampled_out/drained/disabled），每份缺席答复携带采集器计数与固定说明——无记录不是「应用未发包」的证据） |

## 能力状态

| 能力 | 当前边界 | v1 工作 |
|---|---|---|
| 通用代理 | SOCKS5 / HTTP CONNECT / mixed 与多种出站已存在 | 保持标准协议路径，与可选 Mesh 解耦 |
| Linux TUN | TCP/UDP 接入共享路由；有本机进程注解 | 完整身份、双栈旁路、权限与恢复强化 |
| 其他平台 | 有构建/宿主脚手架；Android 仍为有限 demo，iOS 有私有 fd 依赖 | Windows/macOS 正式接管与本机身份；移动完整数据面与公开 API |
| Clash/Mihomo | 拉取/转换/更新链路存在，但语义只部分兼容 | 来源替换、provider、保真组/规则和严格诊断 |
| 多场景 | `profile` 在配置期填充默认值；已有规则可分别选出口 | 并列 ScenarioPolicy、资源预算和有类型的质量闭环 |
| 诊断 | 聚合统计、组状态、Mesh dry-run、diagnose、真实逐流轨迹、纯 Explain、显式 Probe 与可选 stdio MCP 适配器 | 六平台诊断验收与其余 v1 场景策略 |

RouteDecision/RoutePath 已包含组、链路与原因；v1 的 RoutePlan 在其上扩展，不新增第二套路由器。`plan` 模块（RIL-006）把规则结果冻结为只读 `DecisionSnapshot`，执行结果（拨号成功/失败）与规则结果分离，经 `SessionPin` 把流钉在明确代际上，TCP 字节流与 UDP 数据报关联在类型层面分侧。质量样本契约（RIL-026 `quality` 模块）：metric/source/target/count/time/validity 全字段类型化，连接失败率与丢包率是不同指标（拨号来源的旧 `packet_loss_rate` 迁移时改名），未知/过期显式报错不当零，丢包样本必须说明测量对端。订阅已有 SHA-256 变更检测，但不能据此声称有来源签名或新代际事务；不可变代际契约在 `rillane-config`（RIL-003 `RuntimeGeneration`）。出口建立通道契约（`outbound` 模块，RIL-097）把「建立通道」与「业务搬运」分开：`OpenContext` 携带 session/attempt/generation 身份与截止时间、取消信号，但**不持有可重新求值的路由器**——出口只做一次建立尝试，回退归会话执行器按 RoutePlan 编排；`OpenedStream`/`OpenedAssociation` 持有协议包装后的 IO 与握手结果（加密/分帧状态随 IO 生命周期，不泄露给普通复制循环）；`TargetBinding` 区分固定目标与多目标映射；`OpenError` 分阶段携带稳定原因码、可重试性、证据类型（预测/观测/推断/未知）与已脱敏上下文。入口两阶段接入契约（`inbound` 模块，RIL-096）把「认证/解析」与「路由」分开：`PendingStream` 独占客户端通道与一次性 responder，**出口成功后才回复成功**（成功回复写失败在 `accept` 内就地释放已建立出口），丢弃不消费即关闭通道且不触发回复；UDP 准入（`PendingAssociation`）钉住来源校验、显式目标绑定与控制链回收；TUN 会话带 `Capture` 来源标记，回复由网络栈驱动，不套用代理回复模型。会话执行接线（`session` 模块，RIL-098）是这些契约之上的一条权威执行路径：出口建立复用 `SessionExecutor` 作为唯一选路实现（回退对账在 `attempts`——A 失败 B 拨通可追踪），成功回复只在出口建立之后发出；业务字节一旦交换，任何失败都按 `TransferFailed`/`session.cancelled` 携带方向与已交换字节数终止——**不发起第二次出口建立**（重连是新会话的新决策）；有界分片泵读一写一（背压）并按 TCP 语义半关闭；数据报中继逐报文校验目标绑定与上限（显式计数拒绝，不静默截断），控制链关闭即回收。拨号与组合边界（`underlay` 模块，RIL-099）冻结合法路径的传输侧（VLESS over WS over TLS：Dialer 建 TCP → TLS → WS → 协议握手——顺序是协议要求，不是自由 middleware 组合）：底层拨号器是 socket 打开的唯一地点（DNS 解析、接口绑定与旁路都在这里落地——`DialOutcome` 诚实记录旁路是 `Applied`、`NotConfigured` 还是 `Degraded`，降级绝不冒充成功）；`TransportStack::build` 把声明的承载对显式语法表校验（raw、单层 `tls`/`ws`/`grpc`/`httpupgrade`、或 `tls` 打底的两层）——`ws→tls` 内层翻转、同层重复、未知名与原生承载都是装配期 `underlay.stack.*` 拒绝、零拨号；`wrap_chain` 按栈序串联已解析承载、任一层失败即止（不跳过、不回退——回退归会话执行器），原生承载（`quic`、`wireguard`）拒绝包装字节流、自持资源；旁路端口 `PlatformBypass` 把防环做成可注入能力：持有外部库自建 socket 的适配器经原始句柄补施加，旁路必选策略下任何 `CannotInject` 组件（拨号器或承载）在装配期以 `underlay.bypass.uninjectable` 明确拒绝——不留拨号期才发现的防环缺口。权威业务计数（`meter` 模块，RIL-101）在语义等价的业务通道边界设唯一权威计数器：方向统一按客户端→目标/目标→客户端语义定义（API 里不存在 socket 读写方向，计数不随读写翻转），部分写只累加实际过账字节、回退重试不重复业务总量，零长度 UDP 仍计一条报文，发送成功不证明对端已收到——计数面没有「远端已收」字段；A 尝试的真实底层开销与失败照实记录、业务量归属承载 B 恰一次，probe/prewarm 在构造期分类并与用户业务分桶汇总，共享多路复用公共开销不可精确归因时计入显式标记的共享面而不伪造每流精度，入口/出口视图是同一权威量的归属投影——相加不是总使用量。会话观测器（`observer` 模块，RIL-102）承接低频阶段事件：接入/建立/握手/回退/关闭统一携带 session/attempt/generation 关联（逐尝试阶段缺 attempt 即拒绝——关联不做静默补默认；A 失败 B 承载在 establish-failed + fallback + attempt 1 的事件序列里完整可对账），高频字节只走计数器——不为每次读写分配事件，指标投影是 stage×result×origin 的有界枚举积、session_id/域名等高基数身份只进有界诊断尾环不进指标标签，`record` 以 try_lock 永不阻塞转发（争用丢弃计数可见）、统计关闭即纯 no-op，CLI/MCP 经同一 `ObserverView` 读取聚合/尾环/统计同源的诊断视图。诊断事件 Schema（`trace` 模块，RIL-051）把真实连接轨迹类型化：每 TCP 会话/UDP association 一条 `FlowTrace`，携带稳定 `FlowId`、计划代际与 `TraceEvent` 序列——事件序号从 0 连续、成对携带单调时钟与墙钟、逐条稳定原因码与证据类型，预测/观测/推断/未知互不混淆；`detail` 必须已脱敏（载荷/HTTP 内容在 schema 里没有字段可填）；schema 兼容规则主版本精确，更高主版本按 `trace.schema.unsupported` 拒绝而非静默降级。有界采集器（`collector` 模块，RIL-052）在这份 schema 上施加硬资源边界：写路径纯同步永不等待的环形缓冲（满则逐出最旧迹且计数可见）、调用方供钟的 TTL 清扫、确定性计数采样（第一条新流永远入选，内核不引入随机源）、永不丢终态 `Close` 事件的每流上限、拉式订阅背压——慢消费者只是让已关闭迹滞留环形缓冲（滞留量在统计可见），**结构上无法阻塞数据面**；关闭追踪时采集器整体 no-op。真实流生命周期埋点（`session_trace` 模块，RIL-053）骑在权威会话路径上：可选 `SessionTracer` 的本地轨迹恒为权威——不受采集器采样影响（被采样剔除的流仍有完整本地轨迹）；规则/计划按预测证据落点，尝试对账事件逐条携带 attempt_id（A 失败 B 拨通可完整解释），实际出口区分流建立与关联映射，泵实测逐方向首字节时刻（HTTP TTFB 与首个下行字节分立），终态区分正常关闭与控制链回收——时钟锚在开轨时注入、流逝为真实测量，缺少测量证据绝不生成 RTT/丢包。逐连接查询服务（`query` 模块，RIL-055）是采集器之上的读取面：活动/近期连接分页与过滤（匹配总数诚实、近期优先）、以真实 `FlowId` 为锚的单流详情与增量事件读取（ingress/egress 聚合键不会命中任何流），缺席回答逐原因显式——轨迹离开采集器时登记有界墓碑（溢出逐出、TTL 过期、订阅取走、活动上限/采样未准入），「从未见过」「见过但已离开（为何）」「追踪关闭」互不混淆，每份缺席答复携带采集器计数与固定说明：无记录不是「应用未发包」的证据；查询是只读快照，结构上无法偷走订阅者的事件。诊断脱敏边界（`redact` 模块，RIL-057）是 CLI/UI/MCP 共用的输出契约：诊断视图的每一列都必须经 `Redactor` 具名方法产出（方法集合就是白名单——没有附加原始字符串的后门），导出默认对域名/路径/地址/节点名使用稳定别名，本机详细档放大的只是身份字段；**秘密在两档范围内都不出边界**——订阅 URL 剥除凭证与 token/password 类查询参数，错误文本中的 PEM 私钥块与 password/token 键值对替换为占位符，原始配置块只出标签与字节数，日志/订阅名称按不可信文本消毒（零宽与控制字符、长度截断）在两档一致执行。纯 Explain 服务（`explain` 模块，RIL-054）是「为什么这条流走这里」的推演面：规则/场景匹配直接调用 `route()` 的同一组求值函数（不存在第二套匹配器），组状态（健康位/用户选择/链路质量/带宽）经快照显式冻结——同一（配置、快照、输入）三元组离线重放必得同一结论；证据缺失（进程注解缺席、Geo 库未装、域名不解析 DNS、规则集载荷缺席、链路质量无数据）按恒不命中评估并逐条列出缺口，结论标注条件性而非伪装确定；`random`/`weighted`/`round_robin` 在推演中无确定答案——只给健康候选池；全推演无 DNS、无拨号、无 OS 身份查询，输入摘要（SHA-256）随结论输出供诊断对照。

## 控制与配置更新

配置已携带 `version` 字段（当前仅 `1`）：缺省按 V1 适配存量配置，显式未知版本在解析期以稳定原因码 `config.version.unknown` 拒绝。构建能力集（`CapabilitySet`）用于在配置校验期拒绝当前构建不支持的组合（稳定原因码 `config.combo.unsupported`），避免拨号期才失败；缺省能力集为全量，现有调用方零差异。内核 `rillane-core` 不依赖 `rillane-config` 与 Clash 格式，订阅转换收敛于 `rillane-subscription` 侧。

控制面是 `control.api_bind` 上的 HTTP/REST，接口见 [CLI 参考](cli.md)。当前 `/flows` 为入口/出口组合的聚合；兼容 `/connections` 映射同一聚合面并在响应中显式声明语义（`rillane.view: aggregate`——`id` 是入口-出口组合键而非逐连接 flow ID，缺失的时间/域名/规则/链路序列化为 null/空而非伪造值；真实逐连接轨迹归内核查询服务，本聚合视图不替代之）。`diagnose` 按范围选择且默认安全：`safe` 不采集订阅列表/运行配置/完整日志，`full` 在每个出口剥除秘密（配置秘密键、订阅 URL 凭证、日志 key=value 秘密对与 PEM 块），`raw` 不脱敏并显式标注禁止上传；每份清单恒记录范围、需人工复核文件清单与仅限手动的上传政策——rillanectl 不做任何自动上传，诊断包不自动构成可安全上传 AI 的材料。trace 端点（`/trace/flows`、`/trace/flow`、`/trace/events`）以版本化信封（`schema_version=1`）暴露内核逐连接查询服务——以真实 flow ID 锚定、缺席逐因显式回答；Mesh dry-run 不冒充规则解释，也不冒充逐连接轨迹。trace 读面携带详细身份（域名/进程/地址），守护进程配置 `admin_token` 后与 mutating 端点同受权限门（RIL-063：详细身份由权限控制；未配置 token 的本机部署照常开放）；`rillanectl trace inspect <id>` 是交互检查入口——恰一次边界读渲染配置来源定位（代际 + 计划面事件原样；CLI 绝不重新求值规则，重放走同一冻结 Explain 求值器）、分段展开（与路径图共用阶段→层映射，未知阶段显式列出）与下钻指针（增量事件页 + SVG 导出）。`POST /explain` 以同一信封暴露纯 Explain 推演服务（生产求值器 + 冻结快照，零副作用；入口消毒，proto/域名来源非法值以 `explain.input.invalid` 拒绝）。CLI/UI/MCP 经共享 `rillane-app` 边界（RIL-065）消费控制面：闭合操作集——每个诊断调用是一个类型化操作、映射恰一个固定 (method, path)，答复经版本化信封解码、显式缺席与错误分立；管理员级面（原始配置读、订阅 URL、配置写）刻意留在边界之外。MCP 协议与工具契约（RIL-066）在同一 crate 冻结、不引入 SDK：协议版本钉死官方 modern era 修订版 2026-07-28（逐请求在 `params._meta` 声明版本、不符答 `UnsupportedProtocolVersionError` -32022、必实现 `server/discover`、取消走 `notifications/cancelled`——停止处理、释放资源、不答复被取消请求），工具目录与闭合操作集一一对应（16 个工具、类型化输入 schema——未知字段与超限参数在分派前拒绝），工具注解结构性只含 hint 字段、与服务端授权档分立（注解永不充当授权——stdio 服务端本体由 RIL-067 落地）。服务端范围鉴权（RIL-068）在参数校验与执行之前门控每一次 `tools/call`：授权档集合只来自启动配置（默认只读——最小面），授权只读冻结目录的服务端档位字段（永不读注解、永不读请求面任何授权声明字段——直接构造携带 `scope`/`granted`/`authorized` 的调用无法升级范围），拒绝以稳定码 -32001（`mcp.scope.denied` 附所需档名）作答且不进入执行、不消耗配额，固定窗口限速器（默认每分钟 60 次，`--rate-limit 0` 关闸）对窗外调用答 -32002（`mcp.rate.limited`）；凭证留在适配器执行器私有字段，不出现在任何答复/日志里。状态与质量工具（RIL-069）与 CLI 消费同一守护进程载荷——答复信封原文贯通（样本时效经成员 `source` 字段 real/legacy/unknown 表达、缺失样本以显式 null 呈现、绝不补零），且一切工具答复统一过响应字节闸（`MAX_RESULT_BYTES` 256 KiB）：超限载荷以带内 `mcp.result.oversize` 作答（只带字节数——不回显载荷、不写出残缺 JSON），凭证泄漏回归钉住 admin token 在成功/失败答复面均不出现。连接与 Explain 工具（RIL-070）端到端钉住：分页/过滤参数原样到达守护进程查询串，信封逐字节贯通（计划代际与逐事件证据类型保留——predicted/observed 不混淆），一次 tools/call 恰好发出一次边界读（捕获式一次性应答器使隐式二次请求即超时暴露），Explain 工具保持零副作用推演——条件性结论、证据缺口与输入摘要原文贯通（条件性不冒充确定）；查询因此不会隐式增加采集面或额外网络请求，且一切答复都在 RIL-069 字节闸之下。主动探测（RIL-071）带独立授权与配额面：提交/取消在 probe 档之后（只读会话在执行前即拒——-32001，零边界请求），本会话提交的每个作业都与其请求关联登记，释放是结构性的——被取消的调用（无论取消先于还是后于答复）即补发尽力而为的 `POST /probe/cancel`，显式取消成功即解除登记，EOF 退出对仍未释放的作业逐个补发——探测不活得比会话久、不留无人认领作业；目标永不做客户端预审——内网/任意目标拒绝（`probe.target.out_of_scope`）与预算墙（`probe.limit.budget`）是守护进程策略答复原文贯通，被拒提交不产生作业。不可信内容与泄漏回归（RIL-072）钉住其余各面：守护进程载荷字符串携带零宽字符、CRLF、ANSI 转义与伪 JSON-RPC 文本时只能作为数据贯通（序列化恒单行——载荷变不成第二条协议指令，后续协议行不受影响）；边界调用参数无法注入请求（控制字符在 ops 层消毒、查询串值面在执行器百分号编码——CLI 同享——`&`/`#`/`?`/空格/`%` 变不成参数分隔符或新请求行）；超大守护进程载荷以有界 `mcp.result.oversize` 信封作答且无回显；详细身份档既打不开 probe 门（仍 -32001 且拒绝数据无请求回显）也不改变失败路径的保密面（任何答复无凭证）。

配置事务闭环（RIL-079）让 CLI 与 MCP 走同一扇门：守护进程侧 `ConfigTxService` 把纯面提案/批准/应用/回滚（RIL-073–077）装配在 `POST /config/proposals`、`/config/rollback-proposal`、`/config/preview`、`/config/approve`、`/config/apply`、`/config/rollback` 与读面 `GET /config/state`、`/config/receipts` 之后。基准代际、live 内容摘要与回滚候选身份全部由 daemon 自填——客户端无法转述 live 面，因此无法绕过版本/内容前置检查（`apply.base.conflict` / `apply.hash.conflict` 以 409 稳定码信封作答）。批准是操作员真实决定：凭证绑定提案摘要、所有者、范围与有效期且恰好一次性核销——daemon 不自我批准；回滚提案携带标记范围，正向与回滚两路不能互串；同幂等键换身份即拒（`apply.key.mismatch`）。正向执行器做 merge patch（RFC 7396）→ 反序列化 → 能力集校验 → 翻新 live 面；退役内容进入有界历史供回滚执行器恢复（候选不在历史即显式作答、不冒充恢复）。`GET /config/receipts` 给出回执链（seq 降序）与 daemon 自身 live 面的 reconcile——OS 执行侧接线仍归发布协调器工作（RIL-019/081+），本面 `os_applied` 语义是「daemon 配置内容账 + 代际账已落地」。全部写端点在配置了 `admin_token` 时处于权限门之后，`config` CLI 子命令走同一组端点、无本地旁路。MCP 提案工具（RIL-080）把冻结目录扩到 13 个条目、走同一扇门：`validate_config`（read 档）是恰一次 `POST /config/preview` 只读投影——脱敏 diff、诊断与范围越界，不落提案、不激活任何配置；`preview_config_change`（write 档）经 `POST /config/proposals` 登记提案，返回服务端提案 ID、基准代际、有效期与提案期预检（与登记同锁同刻——diff 就是登记依据，不是事后另算的近似）。提案答复不回显补丁（调用者自给自足——大补丁不占答复、秘密值不多一处副本），且适配器把提案所有者固定为 `mcp`——模型面 schema 没有 owner 字段（`additionalProperties:false` 即拒），冒充他人在结构上不可能；批准与应用不在工具面（操作员经 CLI 或独立授权完成），所以只读会话不能拿预览激活任何东西：预览的答复只是投影，从预览到激活的路径必经工具面够不到的显式批准门。配置端点答复携带版本化信封（`schema_version=1`，字段保持平铺——CLI 消费者不受影响），预检答复的秘密脱敏已经过工具端到端验证（触碰 `control.admin_token` 的补丁在 diff 两侧都答 `[redacted]`）。 MCP 应用与回滚工具（RIL-081）闭合事务环且不开任何任意管理 API 逃生口：`apply_config_change`（write 档）只消费**操作员签发**的凭证——schema 同时要求 daemon 签发的提案 ID 与批准 ID，适配器把应用 owner 钉死为 `mcp`（为其他所有者签发的凭证在结构上花不掉），幂等键缺省由双 ID 确定性派生（`mcp-{proposal_id}-{approval_id}`，可显式覆盖），重复调用因此回放同一回执（`phase: replayed`）而不是二次执行；`rollback_config` 两阶段——不带凭证时经 `POST /config/rollback-proposal` 登记 daemon 自建的回滚提案（目标回执须在账、`Applied` 且属 `mcp`），双凭证在场时经 `POST /config/rollback` 以回滚专用键前缀（`mcp-rb-…`）执行，只带一侧凭证是非法输入、在任何边界请求之前即拒（半凭证不是授权面）；`config_audit`（read 档）读回执链与对账结论——只读会话能核实改了什么、live 面与账是否一致；线上端到端闭环 提案 → 操作员批准（`rillanectl config approve --owner mcp`）→ 应用 → 重放 → 审计 → 回滚登记 → 操作员批准 → 回滚执行 复原了原始代际、drain 期限被遵守、既有连接被诚实报告为钉在原代际（不冒称恢复任何连接）。

`rillaned` 从 `RILLANE_CONFIG` 读取启动配置；没有通用文件 watch、SIGHUP 重载或 `rillanectl reload`。已有订阅和控制面更新路径不等于 v1 的跨 OS 代际事务。路由/DNS/防火墙变更的副作用契约（`side_effects`：变更日志、所有权登记、幂等撤销——只撤销本实例条目，既有系统配置只登记不撤销）已就位，Linux 执行侧接线归配置发布协调器（RIL-019）。当前按名称追加的合并、组语义与 interval 单位缺陷见[研究证据](research/proxy-architectures-2026-11-14.md#verified-gaps)。
