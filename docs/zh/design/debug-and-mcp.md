# Debug、路径解释与可选 MCP

状态：**目标设计，尚未实现**；2026-11-14。承接[目标架构](architecture-v1.md)与概念 C31；实施入口为仓库根目录 `todo.md`。本文中的新命令、API 和 MCP 工具都是拟议接口，不是现有功能说明。

## 1. 为什么这样设计、借鉴了什么

Mihomo 的连接观测、sing-box 的类型化接口与宿主边界、Surge 的请求诊断及真实连接反馈，分别提供了观测入口、模块边界和产品解释的参考，详见[研究与官方来源](../research/proxy-architectures-2026-11-14.md)。Rillane 在此基础上让 CLI、界面和 MCP 共用诊断与配置应用服务，复用生产路由器。AI 不参与逐包转发，也不维护第二份路由逻辑。

| 抽象 | 为什么独立 | 优势与成本 |
|---|---|---|
| RouteExplanation | 规则推演没有真实连接，不能当成成功证据 | 离线复现、配置预览；需要固定代际和输入证据 |
| FlowTrace / TraceEvent | 真实连接包含多次尝试，最终出口可能不同于计划 | 定位 DNS、归因、规则、选点或拨号故障；需要有界采集与留存 |
| ProbeJob | 主动探测会访问网络，与纯查询的权限不同 | 可取消、限速、有目标范围；探测结果也不代表所有应用体验 |
| DiagnosticView | 内部快照可能含密钥、应用历史和不可信文本 | CLI/UI/MCP 统一输出契约；需要字段白名单与脱敏回归 |
| ConfigProposal / ApplyReceipt | 校验通过不等于有修改授权，也不等于系统变更完成 | 变更可预览、审计、回滚；需处理并发、崩溃和补偿 |
| MCPAdapter | MCP 是可选客户端适配层 | 核心不依赖模型或 MCP SDK；需要协议版本、鉴权和工具契约维护 |

这些是 C31 的细化，与 C12 来源、C14 代际、C18 计划、C23 会话绑定及 C30 生命周期组合，不要求立即为每个概念新建 crate。

## 2. 当前已有能力与缺口

| 当前入口 | 能做什么 | 不能据此声称什么 |
|---|---|---|
| `rillanectl stats`、`group` | 聚合流量、组与质量状态 | 完整逐连接生命周期 |
| `rillanectl switches` | Mesh 切换记录 | 普通订阅节点的完整选路历史 |
| `rillanectl chain dry-run` | 受管 Mesh 链路预检查 | 任意进程/域名规则的生产路由推演 |
| `rillanectl diagnose` | 收集配置、日志、运行快照 | 整个包已适合发送给 AI；运行配置等仍需逐字段审查 |
| 当前 `/flows` | 入口/出口组合的流量聚合 | 每条连接的稳定 ID、实际起止时间与路径 |
| 当前兼容 `/connections` | 由聚合数据生成的兼容视图 | 真实连接详情；当前缺失域名/时间等字段不能补造成观测值 |

当前没有 MCP 服务。迁移时保留已有聚合指标，并为真实连接建立独立数据契约；兼容 API 必须披露字段可用性，避免把未知填成误导性的成功或真实时间。

## 3. 三种诊断模式

### 3.1 Explain：纯规则推演

输入固定 `generation_id`，入口、协议、源/目标地址、域名及其来源、可选本机应用身份；离线输入的进程身份标记为调用者提供，不能用于实际流量授权。调用与生产一致的规则求值和候选选择逻辑，使用冻结的组状态/质量快照，不拨号、不刷新 DNS、不主动查系统进程。

输出命中的规则及来源位置、候选被排除的理由、场景、逻辑组、预测出口、能力/预算限制、未知字段和置信依据。缺少 DNS、进程或质量证据时返回条件性结果，不能编造确定选择。输出携带输入摘要、配置与质量快照版本，可离线重放。

### 3.2 Trace：实际连接轨迹

每个 TCP 会话/UDP association 生成稳定 `flow_id`，每次拨号有 `attempt_id`；事件带序号、单调时间、墙钟、代际和原因码。记录：

```text
接管 → 上下文/身份 → DNS 或 sniff → 规则/场景 → RoutePlan
     → 候选/拨号尝试 → 实际出口 → 传输统计 → 关闭/失败
```

展示计划与执行差异，例如选中 A，但 A 拨号失败后在允许策略内使用 B。事件区分 observed（实际采集）、inferred（由证据推断）、unknown（不可得）。DNS 预取可能先于应用流，不能用共享 DNS 请求强行反推出进程。

| 路径层 | 可展示的内容 | 边界 |
|---|---|---|
| 策略路径 | 规则、来源、组、场景和预测出口 | Explain 是推演 |
| 连接路径 | 实际连接地址、协议、代理端点及失败尝试 | 连接建立不证明远端目标应用成功 |
| Mesh 逻辑路径 | 自己管理且有遥测的节点链 | 不推断第三方机场内部网络 |
| Internet 三层路径 | 显式 traceroute 类探测得到的响应 | 可能不完整/不对称，不等于代理业务路径 |

采集默认不记录载荷、HTTP 内容或完整浏览历史。设置活动流上限、环形事件缓冲、采样、TTL、每流事件上限和订阅背压；丢事件/截断必须显式返回计数。关闭详细采集后，路由与转发仍正常运行。

### 3.3 Probe：主动验证

DNS、代理握手、目标连接、具备对端支持的 UDP 回显都是独立 ProbeJob，记录探测源、目标、样本种类、数量、时间和超时。为调用者设置目标白名单、并发/速率/总流量预算、取消与结果保留期限；禁止由订阅文本或日志诱导任意内网扫描。真实游戏包丢失率需要对应观测能力，连接失败率不能替代它。

## 4. CLI 与路径视图

拟议 `rillanectl explain`、`trace`、`probe`、`config preview/apply/rollback`，实际语法在实现时冻结。提供人读文本和版本化 JSON；相同输入经 CLI、界面、MCP 得到相同诊断语义。第一版路径视图可用终端和导出 SVG，后续界面通过同一只读 API 绘制，不能另外推算选路。

视图逐段显示输入证据、规则来源、计划出口、实际出口、耗时与失败原因；缺失信息留空并解释原因。导出默认用别名替代敏感域名、应用路径、节点地址和凭证；本机详细查看需要单独权限。动态 SVG 必须转义不可信文本，导出的链接不能执行脚本。

## 5. MCP 装配与权限

建议提供可选独立程序 `apps/rillane-mcp`，默认不启动，先支持本机 stdio。客户端凭证留在适配器侧，不进入模型上下文。它只调用窄化的诊断/配置应用服务，不提供 shell、任意文件读写、通用 HTTP 转发或原始管理员 API 代理。

| 工具（拟议） | 服务行为 | 权限/副作用 |
|---|---|---|
| `get_status` / `list_flows` | 状态、分页摘要及截断说明 | 脱敏只读；身份和历史另设范围 |
| `get_flow_trace` / `explain_route` | 已采集事件/纯规则推演 | 只读；trace 查询不隐式启动无限采集 |
| `get_policy_quality` | 有类型、时效和来源的质量样本 | 只读，未知不是零 |
| `run_probe` / `cancel_probe` | 创建/取消有界探测作业 | 单独的网络探测授权 |
| `validate_config` / `preview_config_change` | 验证候选、生成变更 diff 和影响报告 | 可创建有界临时提案，不改变有效配置 |
| `apply_config_change` | 应用已授权、未过期的提案 | 配置写权限，检查版本与审批范围 |
| `rollback_config` | 按回执恢复已验证版本 | 配置写权限，重新校验能力与外部状态 |

服务端分别检查只读、详细身份、探测和写入范围；工具注解及提示词不是鉴权。用户可以预授权限定范围的自动修改，不能把“每次必须人工确认”写死为协议要求。越出授权范围必须拒绝；默认只读不会因模型声称已获同意而升级。

stdio 的 stdout 只写协议消息，日志到 stderr；选用实现时支持的 SDK 并固定协议/SDK 版本，验证启动、EOF 退出、取消、超时与错误结构。若未来增加 HTTP，另做监听范围、会话/来源校验和相应授权设计；不直接暴露 daemon 管理端口。本提案参考官方 [stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)、[工具](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[授权](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)文档，版本信息以实施时锁定结果为准。

OpenWrt 仅按资源预算选装。Android/iOS 不默认在 VPN 服务/扩展中运行 MCP：先提供授权宿主 IPC 或脱敏诊断导出，必要时由桌面适配器接入；不新增默认手机入站管理端口。

## 6. AI 辅助配置的完整闭环

```text
读取脱敏证据 → 提出候选 → 验证/推演 → 显示 diff 与影响
  → 检查预授权或取得批准 → 应用 → 验证有效代际与连通性 → 必要时回滚
```

ConfigProposal 保存服务端规范化 patch、基础代际/内容哈希、所有者、有效期、变更范围及验证报告。返回不可猜测的 proposal ID；批准绑定具体内容，不能让模型以修改参数重用批准。应用时重验当前代际与授权，过期或并发改变返回冲突，不覆盖人工修改。使用幂等键和 ApplyReceipt，客户端超时重试不能重复执行系统副作用。

配置持久化、OS 副作用和运行时代际遵循同一事务/补偿模型，不能只改内存。重启后根据日志恢复一致状态；失败回执说明补偿是否完成。回滚是重新校验的配置切换，不保证恢复旧连接。修改管理通路时提供宿主侧看门狗与限时恢复，恢复成功须验证，无法补偿则返回明确的恢复步骤。

MCP 输出采用结构化字段白名单；原始 `diagnose` 压缩包不能直接作为模型输入。订阅 URL、密码、私钥、token、原始运行配置默认不出边界；域名/路径等细节需要范围授权。订阅名称、日志、注释是**不可信数据**，不能变成工具指令。审计记录调用者、授权范围、提案摘要、结果及代际，不保存原始秘密；限长、分页、TTL 和错误输出同样受约束。

## 7. 交付顺序与门禁

1. 共用诊断契约、真实流事件、纯 Explain、脱敏视图；验证没有网络副作用和热路径阻塞。
2. CLI 路径检查、主动探测、文本/JSON/SVG 输出；区分预测与观测，验证有界资源。
3. 默认关闭的 stdio 只读 MCP；验证工具输出与 CLI 一致、无凭证泄漏和权限提升。
4. 提案预览与受控写入；验证并发冲突、幂等重试、越权、部分失败、崩溃恢复和看门狗。

六平台构建不能代替真机验证。逐平台报告诊断字段与权限可用性；不支持进程归因的平台明确返回 Unsupported。详细原子任务、依赖和验收条件以根目录 `todo.md` 为准。

## 8. 链路诊断的实施规格

交付顺序固定为：**真实连接列表 → 逐连接时间线 → 规则解释 → 主动探测**。共用事件/身份/脱敏契约先准备；Trace CLI 可先交付，Explain 复用生产求值器后接入。只读 MCP 使用相同事实，不等待探测、图形界面或配置写入全部完成。

| 排错问题 | 必需证据 | 无法确定时的表达 |
|---|---|---|
| 为什么没有连接记录？ | 接管状态、系统路由/旁路快照、入口计数、采集开关和丢事件计数 | 未观察到连接；可能未接管、被过滤或未保留，不能直接判定应用没发包 |
| 为什么选了这个节点？ | 代际、规则来源、身份状态、组成员快照、选择原因 | 身份/样本不足时给条件性解释 |
| 实际走了哪个出口？ | 每次 attempt、协议握手结果、实际端点和回退依据 | 选中不等于连通，代理连通不等于目标应用成功 |
| 慢在哪？ | 可观测阶段的起止/耗时、排队与首个下行数据 | 并行阶段不能简单相加；远端内部耗时不可得时标为 unknown |
| 为什么断了？ | 错误阶段、原始错误码、关闭方证据、网络变化和撤销事件 | 超时不直接归罪节点；区分已确认原因、候选原因与未知 |

网页诊断记录 DNS（缓存/真实查询）、代理 TCP/QUIC 连接、可见协议握手、首个下行数据和吞吐。只有掌握 HTTP 请求/响应语义时才称为 HTTP TTFB；透传 TLS 不凭字节流虚构网站内部或 TLS 阶段耗时。基础连接诊断不要求 MITM。

游戏诊断记录 UDP association、映射生命周期、出口变化、上下行计数、本地队列深度/丢弃与切网。RTT/抖动/真实丢包须带测量方法、样本和对端能力；没有回显/序号证据时保持未知。空闲期间没有下行数据不等于丢包。

第一版必须包含四组复现：未接管/记录被采样删除、规则选错出口、A 超时后按允许策略回退 B、UDP 映射到期重建。每组展示输入、观测事件、推演差异和未知项；CLI、JSON 与后续 MCP 输出语义一致。受管 Mesh、代理端点与 Internet L3 探测分层呈现，不推断第三方机场内部路由。

本节是 v1 的实施规格；API/CLI 精确 schema 随对应任务冻结，Windows/macOS 身份与 Apple 包桥接仍需技术探针和真机验证。

接入/出口接口、会话所有权、合法传输组合与分层流量统计统一见 [v1 IO 与统计契约](io-and-accounting.md)。

DNS/嗅探来源、媒体检测和 Git/SSH/GitHub 连通性的证据与作用域见 [UI 与网络控制规格](ui-prototype-v1.md)，复用 ProbeJob/DiagnosticView/配置提案；不同检测与预热流量不混用户业务统计。
