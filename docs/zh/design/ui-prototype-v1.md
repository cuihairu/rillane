# v1 UI 原型与网络控制语义

状态：**视觉原型与交互规格，功能尚未整体实现**。本轮先保存原型图，不实现客户端。所有节点、流量、延迟、检测结果都是示例；“v1”指设计版本。原型图库与图片清单见 [原型交付说明](ui/README.md)。

## 1. 信息架构与参考来源

桌面覆盖 Windows/macOS/Linux：总览、节点与订阅、规则与区域、网络与 DNS、连接诊断、开发者代理、设置。OpenWrt 后续通过受权控制面复用，不承诺相同原生桌面 UI。

iOS/Android 使用首页、节点、连接、设置四个底部入口；连接开关、代理模式和常用节点靠前。网络设置承载 DNS/嗅探，首页只显示摘要；更深入的规则/诊断逐层展开。移动端不提供任意第三方进程分流；Android 可选应用名单不作为 v1 UI 前置。

Clash Verge 参考其侧边导航、系统代理/TUN、订阅与分组选择；移动参考 Shadowrocket 的连接开关、列表与配置入口，Android 使用 Material 风格。Rillane 加入并行 game/web、路径解释与默认只读 AI。参考来源： [Clash Verge 官方仓库/预览](https://github.com/clash-verge-rev/clash-verge-rev)、[Shadowrocket App Store](https://apps.apple.com/us/app/shadowrocket/id932747118)。不复刻图标和品牌，也不声称存在官方 Android Shadowrocket。

iMac 已通过 SSH 确认有 clash-verge/clash-verge-service/verge-mihomo 进程；未找到可用 cua-driver，未读取到实际窗口截图。本轮依据官方预览作视觉参考，没有据此声称检查了用户实际设置。原始参考截图不放入原型图库，避免混同为 Rillane 产物。

## 2. 三组独立控制

| 控制层 | 选项 | 作用 |
|---|---|---|
| 流量接管 | 系统代理 / TUN / 平台 VPN | 决定哪些流量进入内核；代理模式不能接管未进入的流量 |
| 选路模式 | 规则 / 全局 / 直连 | 决定已接管业务流量如何选出口 |
| DNS 应答与识别 | fake-ip / redir-host、嗅探 | 决定返回什么 IP、怎样保留/补充域名证据；不决定是否代理 |

系统代理与 TUN/VPN 的可用性由平台能力决定。权限不足、服务未就绪与不支持必须展示原因，开关不能假装成功。模式/配置变更走候选验证、diff、应用、确认有效代际；默认影响新会话，旧会话保留出口。可另选“关闭已有连接”，明确会中断连接，不默默重建。

## 3. 规则、全局与直连

| 模式 | 行为 | UI 必须解释 |
|---|---|---|
| 规则（默认） | 本地/订阅规则、区域与场景按明确优先级求值 | game/web/general 可并列；进程/域名规则优先级可查看 |
| 全局 | 已接管业务流量走显式选择的全局组 | 普通场景/区域选路暂停，不能继续显示它们“正在生效” |
| 直连 | 已接管业务流量使用 Direct | 不等于关闭 TUN/VPN、DNS、统计或全部系统代理配置 |

选路前的身份认证、资源限制、硬性安全拒绝与防环始终有效；普通订阅 REJECT 规则不是硬性安全拒绝，全局/直连绕过普通路由规则时应在预览里明示影响，不能含糊承诺“所有拦截保持”。控制面、节点引导解析与显式探测有独立作用域，不盲目跟随全局模式。全局出口不可用时按显式失败策略返回，不静默落直连。

模式编译为统一 RoutePlan 的模式入口，不为三种模式建立三套执行引擎。应用回执显示已请求/已生效模式、代际与冲突，CLI/UI/MCP 必须一致。

## 4. 区域绕过与规则来源

提供“大陆直连 · 其余代理”和“大陆代理 · 其余直连”等具名预设，均展示实际动作，不单独使用含义不明的“绕过大陆/海外”。大陆范围来自用户选择的域名/IP 规则集，并展示来源、版本、更新时间；地理 IP 不是用户所在地或内容服务地区的证明。

局域网/代理节点/DNS 引导等旁路独立于区域预设。普通规则模式建议明确顺序：硬性边界 → 用户明确的高优先级应用/域名规则 → 选定区域规则 → 默认动作；导入时展示相对顺序，不能在刷新时改写用户优先级。GeoIP/域名证据缺失或矛盾时使用配置的兜底并显示原因。

全局/直连显示“区域规则已暂停”。切换预设可先用 Explain 展示 GitHub、游戏、国内站点等样例的前后出口。规则来自哪里、为何命中应一键定位到来源对象。

## 5. fake-ip 与 redir-host

| 模式 | 应答与域名关联 | 优势与代价 |
|---|---|---|
| fake-ip | 返回专用虚拟地址，内核保留地址→域名映射，连接时恢复目标 | 可减少必须先真实解析的场景；需映射生命周期、例外与兼容处理，不能保证零 DNS 查询或永远更快 |
| redir-host | 返回真实地址，结合 DNS 记录、有效期与连接证据恢复域名 | 应用看到真实 IP；共享 IP、缓存和应用自行 DoH 可能让域名关联不唯一或缺失 |

此名称参考 [Mihomo DNS](https://wiki.metacubex.one/config/dns/)，Rillane 内部应表示“应答模式”，不与 DNS 上游出站或路由模式共用一个枚举。此页描述目标，不假设现有 DNS 配置已经提供两种模式。

fake-ip 实现包括双栈地址池、TTL/容量/持久化策略、反查、按域名例外与活动会话引用。保留已发布映射及代际，排空前不复用。映射缺失时明确失败/恢复流程，绝不把虚拟地址直接送公网。例外返回真实 IP 仍应记录来源；与真实网段重叠在应用前拒绝。

切换模式时展示 DNS/应用缓存与旧连接的影响，现有会话保留所需映射。明确支持的 A/AAAA 行为、缓存清理和重启策略，不以清空映射冒充无损切换。

## 6. 域名嗅探

提供关闭/按需/配置范围，默认候选为按需补充域名。可读取支持格式的 HTTP Host、TLS ClientHello SNI、受支持 QUIC Initial 等公开可解析元数据；受版本、ECH、加密和超时限制，不承诺总能识别，也不要求安装 MITM 证书。

域名证据区分客户端显式目标、有效 fake-IP 映射、DNS 关联、嗅探与调用者推演输入。默认补充缺失证据；冲突保留各来源并展示，是否允许覆盖路由目标必须显式配置，不能仅凭不可信 Host/SNI 改写认证边界。协议报文仅在首包字节/时间预算内检查，失败放回原始字节且不无限缓存。

嗅探不是进程归因，也不证明对端身份。诊断展示“已观察/推断/未知”、来源与原因；域名细节受脱敏与权限约束，不默认记录载荷或完整浏览历史。

## 7. DNS 代理与防环

DNS 设置分开表示：应答模式、上游传输（UDP/TCP/DoT/DoH 等）、查询出站（直连/指定组/跟随规则）、按域名上游规则、引导解析。DoH 是加密传输，不自动等于经过代理；fake-ip 也不自动解决 DNS 泄漏。

解析上游的域名、解析代理节点的域名与业务域名分别设置 bootstrap/节点解析路径，避免“必须先连代理才能解析代理”。外连 DNS socket 通过平台旁路，避免被 VPN/TUN 重捕获。UI 以一次显式测试展示实际解析器、查询出站、应答模式与观测时间，未捕获应用 DoH 时不能宣称所有查询都已代理。

跟随规则时仍遵守专用 DNS/引导策略、当前选路模式与能力校验。变更导致循环、上游全不可用、能力不支持时拒绝候选或按已声明的兜底执行，不能无提示使用系统 DNS。内核配置与系统 DNS 副作用使用既有事务/补偿契约。

## 8. 流媒体可用性与地区检测

“流媒体解锁”在界面表现为能力检测与出口选择：按选定节点/策略测试服务可访问性和可观测地区，展示服务、方法、出口、时间与结果。状态为未检测/检测中/可用/受限/未知/失败/已过期；不把 HTTP 200、IP 地理位置或第三方推断等同于可播放。

服务端策略、账号、DRM、地区和时间会影响结果。只有公开且可验证的方法能得出对应结论；需要登录/播放才能确认的项显示未知，不收集账号密码、不安装证书、不承诺持续解锁。检测为 ProbeJob，有用户授权的目标、并发、流量预算、取消、缓存和 TTL。

服务规则可引用媒体组；自动换节点必须显式启用并有迟滞，新会话使用新出口，不能保证现有播放跨 IP 无损。结果过期/未知时不盲目自动切换，探测流量和业务流量分别统计。

## 9. 开发者代理与 GitHub

开发者预设覆盖 Git HTTPS、GitHub API、release/LFS/下载对象以及 Git over SSH。域名列表有来源、版本和维护说明，下载目标可能重定向到不同域名，不能承诺一条 github.com 规则覆盖全部流量。

普通 Git/SSH 客户端流量可以经 TUN，或使用经过验证的 HTTP CONNECT/SOCKS/ProxyCommand 接入；“SSH 客户端经代理”与“使用 SSH 协议作为出口”是不同配置。host key、用户认证与端到端 SSH 留给客户端，不接管密钥或自动跳过校验。

页面分三种作用域：Rillane 域名/三桌面本机进程规则、当前终端环境变量、Git/SSH 配置片段。先展示建议、影响和 diff；复制按钮不修改文件。真的写入需显式授权、精确文件/范围、备份、幂等、并发冲突和恢复；不把全局 Git 代理设置当成默认动作。不同操作系统的 shell/ProxyCommand 模板须各自验证，不能假设都有 nc。

Git HTTPS 走 HTTP(S)_PROXY 等受支持环境；SSH 不假定遵守 HTTP_PROXY。GitHub 的可选 SSH 443 使用 ssh.github.com:443，仍是 SSH 不是 HTTPS，按 [GitHub 官方说明](https://docs.github.com/en/authentication/troubleshooting-ssh/using-ssh-over-the-https-port)展示，不能全局改写其他 SSH 主机。移动端仅展示域名预设/设备代理状态，不伪造宿主终端配置能力。

连通性检测区分 DNS、代理建连、HTTPS/Git 请求和 SSH 握手，带出口与时间；不以“可达”声称 clone 必然更快。AI 默认读脱敏证据，配置写入沿用提案授权与回滚。

## 10. 状态、可用性与交付边界

原型显示连接成功等数据仅用于展示。实现必须包含未配置订阅、空节点、无权限、断网、配置应用中/失败、过期探测、身份未知、不同步代际、模式覆盖规则等状态。开启成功以宿主/内核实际回执为准，按钮乐观状态不得掩盖失败。

交互按键盘/读屏、触控目标、明暗主题、文本放大验收；颜色配文字/图标，不靠绿色唯一传达状态。保持窗口与移动安全区，长节点/域名省略但可查看完整脱敏信息。图片是视觉方向，精确字段、错误和权限语义以本页及 IO/Debug 契约为准。

本次图片不构成组件实现，不证明功能已存在。后续桌面与移动客户端分别通过平台验收，现有 Rust 接口和 FFI 不因出图而视为完成。
