# Protocol support (current implementation)

This page records existing boundaries. Future work follows [v1 design](design/architecture-v1.md) and root `todo.md`. Models and scaffolds alone do not prove capability.

## Inbounds

| Type | Supported | Limits |
|---|---|---|
| SOCKS5 | CONNECT, user/password, UDP ASSOCIATE | UDP requires `udp.enabled` and ingress permission |
| HTTP | CONNECT, Basic/Bearer authentication | No complete non-CONNECT HTTP forwarding, cache or MITM |
| mixed | SOCKS5/HTTP detection on one port | Inherits protocol limits |
| Shadowsocks | TCP streams + UDP datagrams on one port; method/password validated at build time (same rules as egress) | SIP003 plugin server face not delivered; UDP requires `udp.enabled` and ingress permission |
| Trojan | TCP streams over TLS with SHA224 constant-time password hash; UDP association rides the same TLS stream (no separate UDP socket) | Cert/key inline PEM parsed at assembly; UDP requires `udp.enabled` and ingress permission |
| VLESS | TCP streams over TLS with constant-time 16-byte UUID auth; UDP association is raw-encoded single-target frames over the same TLS stream (no separate UDP socket) | Cert/key inline PEM parsed at assembly; UDP requires `udp.enabled` and ingress permission; Vision/REALITY server combinations are a separately validated item and are refused when a client sends Vision flow addons; packetaddr/xudp server faces not delivered |
| VMess | TCP streams over bare TCP with the AEAD sealed header as the auth face (cmdKey derived from UUID; authID CRC + +-120s window + anti-replay cache); UDP association is one-chunk-per-datagram single-target frames over the same connection (no separate UDP socket, no terminating-chunk semantics) | UUID parsed at assembly; client picks the AEAD security per connection (AES-128-GCM / ChaCha20-Poly1305, AEAD-only, alter_id=0); no TLS fields on the server; UDP requires `udp.enabled` and ingress permission; ws/grpc/h2 server carriers not delivered |
| Hysteria2 | TCP streams over QUIC (accept_bi) + UDP datagrams as QUIC unreliable datagrams, both gated behind the HTTP/3 `/auth` face (status 233, constant-time password compare; `Hysteria-UDP: true` declares the UDP face); UDP sessions ride the session table (sticky per QUIC connection, revoked on close) | Cert/key inline PEM parsed at assembly; ALPN always `h3`; UDP requires `udp.enabled` and ingress permission (undeclared server self-refuses at the client); obfs/Salamander, masquerade, ACME, Brutal congestion control and the traffic-stats API not delivered |
| Hysteria (v1) | TCP request streams + UDP datagram sessions over QUIC, gated behind the control-stream auth face (version byte `0x03`, nonzero-rate hard check, min-swap rate grants, constant-time password compare); UDP sessions ride the session table (session id per connection, deleted on stream EOF) | Cert/key inline PEM parsed at assembly; ALPN always `hysteria`, TLS 1.3 minimum; `up_mbps`/`down_mbps` are server rate caps (`None` uncapped, `0` refused at assembly); UDP requires `udp.enabled` and ingress permission; obfs/wechat/faketcp packet transports, ACL routing, ACME, Brutal congestion control and the traffic-stats API not delivered |
| ShadowTLS | v2 carrier ingress: pure TLS relay to the handshake site + HMAC-SHA1 challenge-response switch; switched streams handed verbatim to the inner data server (usually a Shadowsocks ingress bind), fake-record framing both ways after the switch (content ≤ 4091) | Carrier only — no addressing/UDP face (router/output untouched); v2 only (v1/v3 refused by name at assembly); >3 challenge mismatches or any malformed record shape degrades to a permanent innocent relay (the handshake site's full TLS face — active-probing defense) |
| TUN | Shared Linux TCP/UDP data plane | Other platforms need complete integration and runtime evidence |

## Outbounds

| Type | Current carriage | Important limits |
|---|---|---|
| direct | TCP/UDP | Bypass required; TCP fwmark does not prove every UDP dial avoids loops |
| SOCKS5 | TCP tunnels + outbound UDP ASSOCIATE (RFC 1928 §6/§7, source verification + FRAG≠0 drop) | HTTP CONNECT remains TCP-tunnel only |
| AnyTLS | TCP over TLS with session reuse; UDP-over-TCP (UoT) | Subscription alpn/client-fingerprint do not enter the IR (named in the report) |
| Shadowsocks | TCP/UDP; SIP003 bridge for TCP | Plugin mode has no UDP; methods follow dependency/runtime validation |
| shadowsocks-shadow-tls | SS TCP face carried over the ShadowTLS v2 carrier (self-written face; official ihciah/shadow-tls v0.2.20 wire mirror, contract acceptance) | v2 only — v1/v3 refused by name (no silent downgrade); carrier has no addressing face — target addressing belongs to the inner SS protocol; no UDP face anywhere — the combo node takes no UDP connector (build-time scan refusal under udp.enabled); SIP003 plugin not combinable with this combo |
| Trojan | TCP/TLS and supported transports; gRPC gun connection reuse (reuse knobs) | No promise of UDP/all upstream extensions |
| VLESS / VMess | TCP, WebSocket, HTTPUpgrade, gRPC (gun connection reuse, mirror-peer acceptance), HTTP/2; XHTTP (**VLESS only**, over TLS1.3/H2, packet-up/stream-one modes, mirror-peer acceptance); REALITY over TCP (client side); XTLS Vision framing over tcp+TLS/REALITY (mirror-peer acceptance); UDP (**VLESS**: raw/xudp/packetaddr packet encodings, mirror-peer acceptance; **VMess**: raw single-target face) | Validate transports/encryption; XHTTP requires `network: xhttp` and always layers TLS, `xhttp_mode` limited to `auto | packet-up | stream-one` (others refused by name at dial time; stream-up/H3/H1.1 carriers not delivered); REALITY requires `network: tcp` with its own TLS posture; Vision requires `flow: xtls-rprx-vision`, tcp network and a TLS1.3 outer handshake, other flow values refused by name at dial time; `grpc_reuse` gun knobs only on `network: grpc` (refused at build time on other transports; all three absent = single connection with full stream reuse); `packet_encoding` (VLESS) limited to `raw | xudp | packetaddr` (default raw, build-time whitelist), VMess subscription `packet-encoding` limited to `raw` (xudp/packetaddr refused by name); VMess requires AEAD/alter_id=0 |
| Hysteria2 | TCP streams over QUIC; UDP datagram face (official UDPMessage over QUIC unreliable datagrams, mirror-peer acceptance) | obfs (salamander) unsupported — refused on both TCP/UDP faces; servers without UDP support refused by name (Hysteria-UDP declaration check); not transparent web QUIC carriage |
| Hysteria (v1) | TCP request streams + UDP datagram relay over QUIC (self-written face; official v1.3.5 wire mirror, contract acceptance) | Transport limited to `protocol: udp` (native UDP QUIC) — wechat/faketcp and obfs packet transports refused by name at dial time, and refused at build time for the UDP-reachable set; `up_mbps`/`down_mbps` of `0` refused by name at dial time; Brutal congestion control not delivered (QUIC default CC, rates declared honestly); port hopping accepted but not consumed; ACL routing, ACME, traffic-stats API not delivered |
| TUIC | TCP streams over QUIC (v5 Connect on bidirectional streams, token auth via TLS keying-material exporter); UDP datagram face (v5 Packet over QUIC unreliable datagrams, per-assoc server socket, client-side fragmentation, mirror-peer acceptance) | v5 only — v4 wire shapes have no code path and are refused by name; `congestion-controller` other than `cubic` refused by name at dial time (no silent downgrade); no error-response face — refusals arrive as stream/QUIC teardown |
| WireGuard | Userspace TCP/UDP carriage | Some targets use rejecting stubs; cross-build is not runtime proof |
| Snell | Snell v4 TCP record stream (AES-128-GCM records keyed by Argon2id(psk, salt, t=3, m=8KiB, p=1)[:16]; first record carries salt + random initial padding, even-index padding/payload cipher swap, zero chunk = clean EOF; client streams immediately after the request and parses the reply lazily on first read — the official binary defers its reply (eager reply-await deadlocks); official zero chunk closes BOTH directions (no half-close read-back); on client-initiated close the official server sends bare FIN without its own zero chunk (tolerated as clean EOF only after we sent ours); self-written face, official sing-snell wire mirror, mirror-peer contract acceptance + official snell-server v4.1.1 real-peer acceptance: loopback roundtrip UP/DOWN 10014/10014 byte-exact with named error-reply path) | v4 + obfs=none only — explicit non-4 versions (v3 is a different framing) refused by name at import; obfs http/tls refused by name (a node carrying them must not silently connect as plain records); no UDP face (catalog udp=false); no server face; protocol-builtin connection reuse not delivered; no real-node acceptance beyond the seat's official-binary loopback |
| SSH | SSH-2 direct-tcpip channel streams (russh 0.65.2 library carrier; mandatory host-key pinning via SHA256 fingerprint compared in the handshake callback — mismatch surfaces expected/actual by name; password or private-key auth exactly-one-of, encrypted OpenSSH keys decoded with passphrase; per-flow one SSH connection) | No host key pin = refused at build (first-use trust-on-first-use is a named downgrade, never silent); both/neither auth faces refused by name at build; no UDP face (direct-tcpip is TCP only, catalog udp=false); no channel multiplexing across flows; no server face; keepalive not configured (idle teardown follows server sshd policy); acceptance against a real OpenSSH sshd peer (handshake/pin/auth/relay contract tests) |
| Tor | Embedded arti-client 0.48.0 client (one shared TorClient per node, lazily bootstrapped on first flow with disk cache; per-flow `isolated_client()` — flows never share circuits; optional channel-fronting proxy `http://IP:port` / `socks5://IP:port` for networks where raw egress is blocked; explicit read→write→flush relay pump — TorTcpStream buffers writes until flush) | No UDP face (client streams are TCP only, catalog udp=false); no server face (onion services not delivered); no bridges/pluggable transports (fronting proxy is channel-level and may not suffice on Tor-blocking networks); host string verbatim — exit-side DNS, fake-ip pools not consulted; multiple tor nodes bootstrap separately; no clash import/export face (mihomo has no tor type — foreign `type: tor` refused at parse, IR tor nodes exported as named skips); acceptance against the real Tor network (bootstrap + two isolated flows + HTTP 200 roundtrip through the fronting proxy) |
| ShadowQUIC | TCP streams over QUIC (library-carried: shadowquic 0.4.12, the protocol's own Rust implementation; direct path `get_conn` → `connect_tcp` — a fresh QUIC connection per flow, 0-RTT handshake resumption when enabled; username/password carried by the JLS camouflage TLS handshake layer — wrong credentials fail at the QUIC handshake stage; SNI falls back to server, ALPN defaults [h3]; congestion control bbr default, new-reno (mihomo key form new_reno)/cubic accepted, brutal/bbr3 refused by name; probe-pinned initial_mtu=1200/over_stream=true; endpoint held by the connector for its lifetime — probe-proven drop-panic nit; in-process library-server-face acceptance: two-round byte-exact roundtrip incl. a 10KB multi-frame payload with FlowReport up/down accounting (10007/10007 per round), second flow through the same connector, wrong-credentials named failure) | zero_rtt defaults false (mihomo's documented default — official server ≤v0.3.11 has a named zero-rtt disconnect bug); no UDP face — both library UDP faces (over-datagram/over-stream) undelivered, `udp-over-stream` tolerated at import without behavior (catalog udp=false); `quic-versions` non-v1 (v2 is a different wire family) refused by name at import; mihomo-private tuning keys (up/down, cwnd, bbr-profile, recv-window family) not in IR; no server face; no public-network real-node acceptance (seat has no raw egress) |
| Others (Mieru, ...) | Not advertised as available | Schema/import fields or research do not establish a connector |

## Optional features and limits

Mesh is managed topology; ordinary subscription nodes do not understand its envelopes. TCP uses versioned envelopes and hop-by-hop mTLS. UDP Mesh without complete secure carriage remains rejected. Replay sequences do not replace integrity/authentication. See [Mesh reference](mesh.md).

Pools, TLS resumption, padding/timing/shaping and WASM middleware are separate configuration capabilities. Proxy prewarming is not website caching. TLS shape presets do not prove exact browser impersonation. Adding delay does not prove game acceleration. See [configuration](config.md) and [v1 measurement/resource design](design/architecture-v1.md).

Clash/Mihomo compatibility is partial. Validate nodes/groups/rules/transports separately. See [verified gaps](research/proxy-architectures-2026-11-14.md#verified-gaps) for fallback/relay/interval and skipped rules. Import success is not semantic fidelity.
